# P29-007 IG備蓄に応じたD4の段階的Iron配分

開始 HEAD: `08fcb509a854414e7f63ce8f59f5f36485aaf4f5`(clean、AGENTS.md なし、既定の P29-007 計画なし)。
P29-006-DIAG-001 の案 A を実装。判定は末尾の「§9 採用判定」(**実装候補・採用判断は条件付き**)。

## 1. 採用した式
- S: 月初の IG 備蓄、D: MilitaryFactory の月間 IG 需要(既存 D4 と同じ `base × level × t` の州合計)、K = 3(`MILITARY_IRON_PRIORITY_IG_RESERVE_MONTHS`)。
- **α = clamp(S / (K × D), 0, 1)**(`military_iron_priority_weight`)。
- Iron の充足率 = `(1 − α) × P + α × M`(`blend_iron_satisfaction`)。P: 需要比例配分(全消費者共通の 月初Iron備蓄 / Iron需要合計)、M: 従来の D4 優先配分(MilitaryFactory は全入力の最も厳しい 備蓄/需要、他消費者は残りの按分 × t)。

### 実装上の配分方法(会計との整合)
- 充足率は「予算 / 需要」で、既存コードでは op の上限として直接使われる(消費量 = `base × level × op`)。そのため充足率の線形補間は、**建物ごとの Iron 配分量(= base × level × 充足率)の線形補間と等価**。
- α = 0 で P、α = 1 で M と**ビット一致**(`(1−α)·P + α·M` を f64 で計算し f32 へ戻す。端点の積は 0 / 1 倍で厳密)。
- 他消費者の `M` 側は既存どおり `others_sat × t`(予算ちょうどに揃える)。P 側は既存 D0 と同じ値(`resource_satisfaction`)。
- 配分総量: 実消費は、既存の `limit_operation_ratio_to_stock` + `consume_inputs_atomically`(その時点の備蓄で原子的に判定)が上限を保証する(P の側が元々 `t < 1` で備蓄を超え得る点も既存どおり)。補間後も備蓄を超えない(保存則の残差 0 で確認)。
- 新しいヒステリシス・永続状態・Save 変更なし。

### 場合分け
| 条件 | 扱い |
|---|---|
| Iron 不足なし(需要合計 ≦ 備蓄) | 従来どおり D0(補間しない) |
| MilitaryFactory の Iron 需要 0 | 従来どおり D0 |
| D = 0(IG を要求しない) | 従来仕様(ゲート `S < K×0` は偽 → 優先配分)を維持して α = 1 |
| S が非有限・負 | S = 0 として α = 0(ゼロ除算・NaN を作らない) |
| S ≧ 3D(境界を含む) | α = 1(従来の D4 と同一) |
