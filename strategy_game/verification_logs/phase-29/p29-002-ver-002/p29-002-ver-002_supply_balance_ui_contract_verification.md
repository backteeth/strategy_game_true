## 4. 発見した不具合と修正

| 項目 | 内容 |
|---|---|
| 不具合 | 収支ブロックのキャッシュ(P29-002 の毎フレーム全 Division 走査の回避)が、日付・軍事登録・実績・言語・プレイヤー国家の変化だけで再計算していた。**備蓄だけが変わり、これらが変わらない場合**(更新順で備蓄の変更が先に起きた場合など)、備蓄日数が古いまま残る |
| 確認方法 | 回帰テストを追加し、修正を外すと失敗することを確認した(備蓄 20.0 に変更しても「備蓄: 90.0日分」のまま)。実ゲームでは日次補給が軍事登録を毎日変更するため他の変更検知に隠れていたが、契約(備蓄が変われば表示も変わる)の取り残しである |
| 修正 | `src/ui/economy_panel.rs` の `update_economy_panel`。キャッシュのキーに「表示対象の国家と MilitarySupplies 備蓄値(ビット値)」を加え、変わったら再計算する。再計算の条件が増えるだけで、表示内容・生産・Save には影響しない |
| 影響範囲 | 表示のみ。ゲーム状態は変更しない(読み取りのみ) |

テストの初回失敗(別件): 新規 E2E の初回実行で「備蓄日数が 1 日分ずれる」失敗が出たが、パネル System が同じフレームの日次補給より先に走ったための 1 フレーム遅れ(次フレームで解消)で、テストの読み取りタイミングの問題だった。実ゲームでは次フレームで更新される。パネルは常に同一フレームのスナップショットから備蓄・需要・実績を読むため、異なる日の値は混在しない。
