## 1. 絶対に押さないもの(ユーザー Save の保護)

保存先は `saves/savegame_v1.ron` に**固定**されており(`src/save/write.rs` の既定値、`SavePathConfig`)、実行時に変更する UI・環境変数・引数はコード上に存在しない。自動保存も無い(`SaveRequestMessage` を発行するのはトップバーのボタンのみ)。

| 操作 | 影響 | 手順での扱い |
|---|---|---|
| トップバーの **セーブ** | 既存 Save を**即座に上書き**(確認なし) | **押さない** |
| トップバーの **ロード** | 確認ダイアログの後に既存 Save を読む | 押さない |
| 国家選択画面の **続きから** | 既存 Save を確認なしで即ロード | **押さない** |
| F1 / F2 / F3 | デバッグ操作(時代進行・鉱床公開・改革即完了) | 押さない(通常プレイの証拠にならなくなる) |

本手順は Save/Load を使わない。ゲームを起動して終了するだけでは Save ファイルに触れない(起動時のファイル I/O は無い、`main.rs` のコメントと `top_bar.rs` で確認)。**Save/Load の動作確認は本手順の対象外**(専用の検証 Save を別パスに置く手段が無いため、今回は手順から外した)。

### 確認 A:Division 詳細と選択更新(停止したまま 5 分)

1. **Ctrl+5** で軍事パネルを開く。「部隊一覧(1 部隊)」に `#id @ Dwarf Mining Region | 待機中 | 兵力:…` が出る。

記録: A-1(詳細項目の識別)、A-2(日数経過での更新、再クリックなし)、A-3(補給 100% でも他が別値になり得る点)。

| 段階 | 押す・選ぶ | 停止して読む値 | 期待する変化(コードからの見込み) |

| B-6 補充 | 自国州に戻った Division を左クリックし、**+1 日・+10 日・+30 日**で停止して読む | 兵力・装備・組織率・補給・準備率 | 兵力は 1 日あたり最大兵力の約 1%、組織率は 1 日 +5(`reinforcement.rs`、`ORG_RECOVERY_PER_DAY`)。**装備は「軍需物資(MilitaryEquipment)」の備蓄から補充されるため、備蓄が 0 なら回復しない見込み** |
| B-7 再攻撃の判断 | 準備率と制約要因を読む | 準備率、制約要因(戦力/装備/補給) | 制約要因がどれか画面から分かること。右クリックで再攻撃できること |

**P27-005 の判定規則**: 次の全てを同時に画面で観測したときだけ、P27-005 の「敵地で攻撃中の Division へ補給が届く」を PASS 候補とする。
1. Division の状態が「戦闘中」で、現在位置が**敵(Arcadia)支配**の州である。
2. 軍事パネルの「進行中の戦闘」にその州の戦闘がある。
3. その Division の「補給(直近の日次補給判定)」が **0% を超える**。
4. その時点の軍用補給物資(MilitarySupplies)の備蓄が正である(0 なら補給 0% は正常で判定不能 → UNCLEAR)。

**自国領での補給確認(B-1)だけでは P27-005 を完了にしない。** 勝利して即座に占領した場合(戦闘が発生しなかった場合など)は P27-005 は NOT REACHED とする。

## 6. 到達できなかった場合の扱い

| 状況 | 記録 | 終了条件 |
|---|---|---|
| 勝利して撤退が起きない | B-5 を「占領」と記録。B-6・B-7 は NOT REACHED | Western Mage Province へ攻撃を続け、戦争が終わるか +30 日で終了。**撤退を作るために条件を変えない** |
| 戦闘が決着しない(同じ州で戦闘中が 30 日続く) | 補給・兵力・組織率を 10 日ごとに記録 | 30 日で UNCLEAR。P27-005 は B-3 が観測できていれば別途判定。多師団戦闘の膠着はコード上の既知の残課題(P27-005 報告書 Medium) |
| 敵 Division が見つからず戦闘が起きない | 無防備な州を占領した、と記録 | その州の戦争目標へ進めて戦争終結まで。B-3・B-4 は NOT REACHED |
| 回復に長期間かかる | 兵力・装備・組織率を +1/+10/+30 日で記録。**+60 日**で終了 | 装備が 0 のまま変わらない場合は、その事実を記録(原因をユーザーが仮定しない) |
| 宣戦できない(休戦・条約・正当化不可) | 画面のメッセージを記録 | 別の Arcadia 州を対象にする。それでも不可なら B 全体を NOT REACHED |
| 命令が出ない(右クリックが効かない) | カーソル位置(UI の上か)、Division が選択されているか、目的州が敵支配か | UI パネルの外、かつ Division 選択中に再試行。それでも不可なら UNCLEAR |

通常プレイで撤退へ到達できない場合の**補助候補**として、既存の診断テスト群(例: `tests/p27_007_zero_damage_battle_termination_e2e_test.rs`、`tests/p27_fu_001_ai_retreat_alternative_e2e_test.rs`)が撤退経路を自動テストで固定している。ただしこれは自動テストであり、**ユーザーの実ウィンドウ確認の代わりにならない**。診断用の資源補充を通常生産の証拠にしない。今回は、通常 New Game で撤退を人為的に作る手順は提示しない(本番コード・データの変更が必要になるため、その場合は NOT REACHED として記録する)。

## 8. ユーザーから結果を受け取った後の判定方法

| 項目 | PASS | FAIL | NOT REACHED | UNCLEAR |
|---|---|---|---|---|
| A-1 | 5 項目(兵力・装備・組織率・補給・準備率)が識別できる | 項目が欠ける・誤った値 | Division を選べなかった | 値が読めない |
| A-2 | 再クリックなしで値が変わる | 再クリックまで古い | 値が変わる条件に到達しなかった | — |
| A-3 | 補給と兵力・装備が別項目として読める | 区別できない | — | — |
| C-1 | 前後で備蓄が増減し、稼働率が読める | 稼働率や備蓄が表示されない | 月次生産に到達しなかった | 変化が読めない |
| C-2 / C-3 | 理由が画面の値だけで判断できる | **判断できない → UI 上の不足として登録(次タスク候補)** | — | — |
| B-3(P27-005) | §5 の 4 条件を同時に観測 | 戦闘中・敵地で補給が 0% で備蓄が正 | 戦闘が発生しなかった | 条件が揃ったか判定できない |
| B-5〜B-7 | 各段階が画面で追える | 状態・値が矛盾 | 撤退が発生しなかった等 | — |

- A・B・C の必須項目が全て PASS または NOT REACHED(理由付き)で、FAIL が無い場合に限り、「UI WINDOW VERIFICATION COMPLETE」を検討する。
- **P27-005 は B-3 が PASS のときだけ完了**とする。NOT REACHED や UNCLEAR は PENDING のまま。
- FAIL・C-2/C-3 の「判断できない」は、それぞれ独立した原子的タスクとして登録する(本書では修正案を作らない)。
- スクリーンショットがなくても記録欄だけで判定する。ユーザーが操作していない項目は PASS にしない。
