# P29-004：補給生産能力に基づく AI 募兵制限

P29-003-DIAG-001 の設計変更候補 E3 を実装した。既存の備蓄(ストック)による AI の募兵判定の**後に**、新しい師団が完成した後の補給需要を、直近の月次生産の実績から再構成した持続的な産出で賄えるかというフロー判定を追加する。

```text
P29-004 COMPLETE
E3 IMPLEMENTED（既存のストック判定に追加。攻勢 70 日分・募兵 40/70 日・E1 の条件は不変）
THE LIMIT WORKS（AI の注文が持続的な生産能力を超えないことを、600 か月の実走で確認）
MINIMUM STANDING FORCE (2 DIVISIONS) EXEMPT — 設計値を 1 つ導入（§3.4。免除なしでは世界が破綻する）
NOT A FIX FOR SUPPLY SHORTAGE / LONG WARS（補給不足・長期戦争は残る。§8）
MANUAL VERIFICATION PENDING（P29-002・E1 の残存手動確認を含む）
```

## 3. 実装(`src/military/production_capacity_gate.rs`、`src/military/ai.rs`)

### 3.1 判定

```text
許可 ⇔ 将来需要(月次換算) ≤ 持続的な月次産出  または  (生存師団 + 訓練中) < 最小常備戦力(2)
将来需要 = 生存師団(満員時の日次需要)の合計 + 訓練中(募兵キュー)の師団の日次需要 + 今回の 1 個
```

- 評価位置: 既存の募兵補給ゲート(`evaluate_recruitment_supply_gate`、ヒステリシス更新を含む)の**後**、人的資源の判定の前。補給ゲートの状態(`recruitment_supply_blocked`)は変更しない。
- 見送り時の結果: `AiRecruitmentOutcome::SkippedProductionCapacity`(新設)。評価自体の失敗(overflow 等)も安全側として見送る。
- 生産が足りるだけでは許可しない(備蓄・bridge・人的資源・目標数・キュー空の既存条件がすべて必要)。備蓄が多くても生産が足りなければ許可しない。

### 3.2 生産能力の見積もりと換算

| 項目 | 内容 |
|---|---|
| 見積もり | 国家が所有する州の MilitaryFactory について、`StateData.building_operation_ratios[MilitaryFactory]`(直近の月次生産で**実際に記録された**最終稼働率。FIX1・D4・入力不足・労働力・物流を反映し、Save V1 に既に永続化されている)× 現在の Level × 基本出力(`buildings.ron` の MilitarySupplies 出力)を、月次生産と同じ式(`calculate_actual_output`)と entry ごとの正規 units 量子化で合計する。理論上の最大出力ではない |
| 換算 | 日次需要(units/日)→ 月次: `ceil(daily × 365 / 12)`(うるう年なしの暦の月平均日数 30.4166…、整数演算)。月の日数(28〜31)で判定が揺れないよう固定の月平均を使う。生産実績の対象年月は「月次処理が走った月」(P29-002)で、見積もりは月初の月次生産と同一フレームで先に確定した稼働率を使う |
| 将来需要の算出 | 既存の正規関数 `division_daily_demand_units`(生存師団。**満員時の需要**にするため、損耗中の師団も `manpower = max_manpower` として評価)と `proposed_division_daily_demand_units`(訓練中・今回の 1 個)。師団ごとに自身の定義の `supply_usage` で算出し、固定値を持たない |
| 採用期間 | 直近 1 か月。理由: 稼働率の履歴を新たに保持すると Save/Load・リセット経路が増える。直近の稼働率なら既存の永続データだけで New Game・Load 後も同じ値が再現できる。一時的な入力不足・物流低下の月は見送られ、翌月に回復すれば許可される(増産・減産に 1 か月遅れで追従) |
| 未集計と生産 0 | 稼働率が**未記録**の MilitaryFactory(Level > 0)は「未集計」(`unreported_entries`)として数え、能力には **0 として加算**する(無限大とみなさない)。記録済みの 0 は「生産 0」。どちらも能力に寄与しないが、診断では区別して返す |
| New Game 直後 | 月次生産(Economy)が AI(CountryAi)より同一フレームで先に実行されるため、記録済みの稼働率で判断する。初回の月次処理前は稼働率の記録がなく能力は 0(テストで確認)。最小常備戦力の免除により、それでも 2 個まで募兵できる |
| Load 直後 | Save 内の稼働率(StateData)で判断する。ledger 等の非永続の履歴に依存しない。Save 前後で再構成される能力が一致することをテストで確認 |

### 3.3 訓練キュー・連続注文

- 訓練中の師団は `country.recruitment_queue` の各項目から将来需要に算入する。
- 同一更新で先に許可した注文は `recruitment_queue` に入るため、後続の判定に自動的に反映される(二重計上も見落としもない)。現在の AI は国家ごとに月 1 件・キューが空のときだけ募兵するため、実運用でキューが複数になることはないが、判定自体は一般のキュー長に対応している(単体テストで 0〜6 件のキューを検証)。
- 目標数と許可の矛盾: 目標数に達していない国でも、生産能力が足りなければ見送る。目標数が下がっても、既存の師団・注文は変更しない(自動解隊・注文取消はしない。テストで確認)。

### 3.4 設計値の導入: 最小常備戦力 2 個(免除)

| 項目 | 内容 |
|---|---|
| 値 | `MIN_STANDING_DIVISIONS = 2`。生存師団 + 訓練中の数がこの数**未満**のとき、生産能力にかかわらず(既存の備蓄・人的資源等の条件を満たせば)新規の 1 個を許可する。3 個目以降は常に生産能力の判定を受ける |
| 理由 | 免除なし(0)で標準シナリオ(E1 適用後)を 600 か月進めると、**全国が初期の 1 個のままになり 1820/06/03 まで戦争が発生せず(20 年間)、その後 Dwarf が 1 州・国庫 −33,819・税率 1.00 へ破綻**し、Arcadia が 8 州・Ferrowyn が 9 州を得る世界になった(`P29_K=0` の実測)。これは P28-011-PRE-003 が予告した凍結・征服型と同じ。免除 2〜3 個では全 6 か国が存続し国庫も正を保った。5 個では 3 か国(Arcadia・Oceanic・Ferrowyn)が消滅した |
| 位置づけ | 指示の「生産能力を超える追加募兵は許可されない」の例外であり、**採否の判断が必要な設計値**。免除を 0 にすれば指示どおりの厳密な制限になるが、上の世界になる(§7) |
