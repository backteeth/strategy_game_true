## 1. 判定単位とその根拠
**国家単位**(国家の全 Factory entry)。
- Iron は国家共通の備蓄で、月次生産の入力充足率(Step 2・D4 の配分)は州ごとではなく**国家単位**で決まる。同じ入力不足を受ける Factory の増設は、建設先の州を変えても同じ制約を受ける。州単位の判定は、建設先を変えるだけで抑止を迂回できる。
- 一方、**全 entry が条件を満たす場合だけ**抑止する。1 つでも正常に稼働している・Iron 以外の理由で低稼働の entry があれば、その国は抑止しない。特定州の低稼働(労働力・物流・破産)を理由に、正常に稼働できる設備まで一律に除外しない。
- 建設先の選定(StateId 昇順の最初の候補)は変更していない。除外は「Factory を建てない」判断全体で、建設先の州ごとではない。

## 2. 入力不足の定義
- 月次生産(`CountryProductionOutcome`)が Factory の entry(level > 0)ごとに観測する:
  - `Iron を除く上限` `free_op` = 労働力・物流・Iron 以外の入力(月初充足率+消費前備蓄による引き下げ)・破産が許す稼働率の上限。
  - **入力不足が実際の稼働制約** ⇔ 実際の稼働率が `free_op` より**厳密に**低い(差 > 1e-6)。
  - 稼働率 < 0.1(**0.1 ちょうどは含めない**。f32 の備蓄上限への 1ulp 切り下げ[0.1 → 0.099999994]を許容するため `< 0.1 − 1e-6`)。
- 数えない: 労働力・物流・破産・Iron 以外の入力による低稼働(`free_op` に反映されるため差が 0)。Iron と他の制約が**同率**(同時に律速)の場合も、Iron は厳密な制約ではないため数えない(保守側)。
- 実績としての稼働率 0 でも、Iron が制約なら数える。Iron が制約でない 0(労働力 0 等)は数えない。
- 稼働率の低さだけからは推測しない(既存の入力充足・稼働率の算出の中で、Iron が制約になったかを直接観測する)。

## 4. 建設候補への統合
- 優先度 3(既存の通常判断)で選ばれた Factory、Mine の候補なし時の Factory フォールバック、優先度 2 の構造的 IG 開発の Factory を、**候補から除外**する。
- 除外時: 優先度 3 の選択肢は Mine か Factory の二択のため他に有効な候補がなく、**建設を保留**する(予算・キュー・国庫を一切変更しない。代替建設への支出移動なし)。既存の建設キューの注文は取り消さない。
- B1 の Mine 判断(優先度 2.8)・原材料不足(Iron < 30)の Mine は維持。Factory の除外だけを理由に Mine を建てず、Factory の最大需要も B1 に加えない。
- ループ防止: 除外は判断ごとに同じ入力から同じ結果で、注文を作らない。次の判断日にも同じ条件で保留されるが、予算・キュー枠を消費しない。
