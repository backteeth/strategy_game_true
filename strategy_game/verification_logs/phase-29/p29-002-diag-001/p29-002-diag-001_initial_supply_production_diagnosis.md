## 3. 原因(2月の生産 0.0)

**MilitaryFactory の入力資源 IndustrialGoods(IG)の初期備蓄が 0 で、初回の月次生産では入力充足率が 0 になり、稼働率が 0 になる**ため、MilitarySupplies の産出が 0 になる。

| 確認 | 根拠 |
|---|---|
| IG の初期備蓄 | `assets/data/countries.ron` の Dwarf Federation の初期備蓄は Food 400・Wood 200・Iron 500・Coal 500 のみ。IG は 0(再現でも 1800/01/01 の IG = 0.0) |
| MilitaryFactory の入力 | `assets/data/buildings.ron`: Iron 30 + IndustrialGoods 15(Level あたり)。出力は MilitaryEquipment 20 + MilitarySupplies 100(Level あたり) |
| 入力充足率の決定時点 | `src/economy/production.rs` の Step 2(月次生産の冒頭): `sat = clamp(月初備蓄 / 需要合計, 0, 1)`。月初の IG 備蓄 0 → MilitaryFactory の IG 充足率 0 → 稼働率 `min(労働力比, 物流比, 入力充足率) = 0` |
| 同じ月次処理内の生産順 | Step 3 は `BuildingType::ALL` の順(Mine → Factory → MilitaryFactory)。Factory が IG を産出(Lv3 × 30 × 0.2353 = 21.18)するが、MilitaryFactory の稼働率は Step 2 で月初備蓄から決まっているため、同じ月には間に合わない |
| 稼働率 0.2353 の根拠(3月) | Southern Industry の物流: 容量 20 / 使用量 85(Factory 3 × 15 + MilitaryFactory 2 × 20)= 0.2353。労働力比は 0.274(就業 110,000 / 総労働力 401,400)で物流が律速 |
| 3月の産出 | Lv2 × 100 × 0.2353 = **47.06**(手動観測 47.1 と一致)。入力は Iron・IG とも十分(IG 21.18 ≥ 必要量) |
| 2月と3月の差 | 2 月の月次処理で Factory が IG を生産して備蓄に入る(21.18)。3 月の月初には IG があるため、入力充足率が 1.0 になり、MilitaryFactory が稼働する |

否定した仮説:

| 仮説 | 結果 |
|---|---|
| UI だけが 0 を表示している | 否定。備蓄の増分も 0(ledger の実産出 = 備蓄に実際に加算された量。P29-002 のテストで固定) |
| 生産そのものが 0 になる不具合 | 否定。入力充足率(IG 0)から正規の式どおり 0 |
| 初回雇用が未確定 | 否定。2 月の月次処理で就業者は 110,000 に確定済み(同じ月次処理内で雇用更新 → 生産の順)。Factory は 2 月から稼働率 0.2353 で稼働している |
| 入力不足(Iron・Coal) | 否定。Iron 500・Coal 500 は十分。不足しているのは IG のみ |
| 対象月の取り違え | 否定(§5) |

## 4. 日次消費と月次生産のタイミング(備蓄切れ期間)

- 初期ブリッジ備蓄 31.0 は「次回の月次生産までの需要」として付与される(P26-004-PRE-005。需要 1.0/日 × (30 日 + 予備 1 日))。1/02〜2/01 の 31 回の日次消費で 0.0 になる。
- 2 月 1 日の月次生産が 0 だったため、2/02〜2/28 の **27 日間**、国家備蓄が 0 で Division の補給充足率は 0%(戦闘準備率も 0%)になる。3/01 に 47.06 が入り回復する。
- P29-001-VER-001 のプレイ B の観測(02/26 の補給 0%・戦闘準備率 0%・備蓄 0、03/06 の補給 100%・備蓄 75)は、この期間に該当する。プレイ A の 1800/02/01 の「備蓄 0 → 補給 0%、3/01 に 36 → 100%」も同じ型である(3/01 の 36 は同プレイの稼働率・物流の差による別個の値で、本診断の再現値 47.06 とは別のプレイの値。差の原因は今回調べていない)。

## 5. 実績の対象年月と画面上の日付

- 実績の対象年月は、月次生産を実行した `MonthChangedMessage` の年月(月が始まる日)である。
  2 月 1 日の月次処理の実績は「1800/02」、3 月 1 日の実績は「1800/03」。
- 画面の日付が 2/01 になった時点で「1800/02」の 0.0 が出る。3/01 になると「1800/03」の 47.06 に置き換わり、その月の間は維持される(§2.1 の ledger 列)。ずれはない。
- 実績(月次生産でその日に備蓄へ加算された量)と備蓄(同日に日次消費を差し引いた値)は別の量である。3/01 の備蓄 46.06 = 実績 47.06 − 当日の消費 1.0。
