## 2. 窓幅 N の選定(4 / 6 / 12)
UI 用 ledger(直近 1 か月・非永続)とは別に、AI 判断用の履歴を持つ(ledger は表示の「未集計」復帰のため Load で消去、履歴は Save で復元)。

### 制御ケース(`supply_production_history::tests::window_comparison_on_cycle_and_permanent_changes`)
| 条件 | N=4 | N=6 | N=12 |
|---|---|---|---|
| 4 か月周期 [280,280,140,100](平均 200)での最大過大評価 | 0 | +26.7(+13%、位相による) | 0 |
| 恒久増産(100→200)で平均が中間 150 に達するまで | 2 か月 | 3 か月 | 6 か月 |
| 恒久減産(200→100)で平均が中間 150 を下回るまで | 2 か月 | 3 か月 | 6 か月 |
| 完全に追従するまで | 4 か月 | 6 か月 | 12 か月 |
| 新規ゲーム開始から通常経路が使えるまで | 4 か月 | 6 か月 | 12 か月 |

- 恒久減産時は、現在設備の推定が上限(min)として即時に効くため、平均の遅れ(N か月)の間も過去の好調な実績で追加募兵を続けない(単体・e2e で確認)。
- 周期(Elfin の約 4 か月)の整数倍の窓(4・12)は周期を完全に平均化する。6 は周期と整合せず、高稼働の位相で過大評価が残る。
- 恒久増産への追従と開始時の保留は、N が大きいほど長い。12 か月は追従に 1 年かかり、保守的すぎる。
- **採用: N=4**(第一候補)。理由: 周期を完全に平均化し、追従遅れが最小で、状態は 4 要素のみ(単純・決定論的)。

## 3. 履歴の仕様
- 記録: 月次生産ごとに (年, 月, units)。生産 0 は `Some(0)`、集計失敗は `None`。
- 重複・過去の月・不正な月(1〜12 外)は追加しない。年越しは 年×12+月 の暦順で比較。
- 窓幅(4)を超える古い実績は保持しない。国家・セッション間は、`HashMap<CountryId, _>` と New Game / Load での置換で混ざらない。
- 平均: 判断月を最後とする連続 4 か月、すべて `Some`、端数切捨て(保守側)。足りない・古い・欠測・`None` を含む場合は `None` → 通常経路を保留。

## 4. 能力上限と単位・処理順序
- 同一フレームの順序は Economy(月次生産・履歴記録)→ CountryAi(募兵判断)。判断時、履歴の最後は今月で、`average_units((year, month))` が今月を要求する(古い履歴は使わない)。
- 将来需要の換算(`ceil(daily × 365 / 12)`、既存の量子化契約)は変更せず、平均・現在設備の推定・需要はいずれも units/月 で比較する。
- 訓練キュー・同一更新の先行注文は、従来どおり将来需要に算入される(連続注文は上限を超えない)。解隊・注文取消は追加していない。

## 5. Save / Load
- 新しい Save: 履歴(対象年月と実績)を保存・復元(e2e: Save→60 日進める→Load で同一)。
- 旧 Save(フィールドなし): 空の履歴として復元(単体テスト)。過去の月は推測して埋めない。**旧 Save をロードした直後は、通常経路の新規募兵が最大 4 か月間保留される**(月次生産が 4 か月分記録されるまで)。最小常備戦力の免除経路は影響を受けない。
- New Game(国家選択への進入): 履歴を消去。ロード時の Load は Save の履歴で置換(`sanitized` で不正な並びは空にする)。
- UI の「未集計」復帰(ledger)と AI 履歴の復元は別系統。`saves/savegame_v1.ron` は読み書きしていない(一時ディレクトリで検証)。
