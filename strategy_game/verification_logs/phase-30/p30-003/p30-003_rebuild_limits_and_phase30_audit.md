# P30-003 軍需工場再建の限界ケース検証・Phase 30 統合監査

開始 HEAD: `52aa78f8a05e3e6207c21298881e5f85bf64861f`(clean)。本タスクで本番コードは変更していない(テストと本報告のみ)。

## 1. 総合判断

- **「再建注文経路の実装完了」**: 達成。AI 国家が条件を満たせば、既存の建設キュー・資金・完成・月次生産・募兵の各経路だけで MilitaryFactory を再建し、募兵まで進む(P30-002 の e2e と本タスクの e2e で確認)。
- **「すべての国の軍備復帰」**: 未達で、本 Phase の範囲外。国内資源を失った国(Oceanic の標準シナリオ=工場・鉱床・師団を失った国)は救済されない。標準シナリオでは再建は発火しない。これは設計上の許容(貿易・輸入・資源獲得 AI は作らない)。
- 本タスクで確認した範囲に、契約違反の欠陥は無かった。確認できた限界はすべて設計上の限界として分類する。

## 2. 入力競合の検証(Iron / IG)

P30-002 の国内供給判定は Iron 供給と IG 供給を別々に必要量と比べる。保証するのは「それぞれの総供給が新工場の必要量以上」までで、既存建物への配分後に残るかは判定しない。必要条件であって十分条件ではない。

検証: `tests/p30_003_input_competition_test.rs`(実際の D4 配分・月次生産を通す、単一の完全雇用州)。MF lv1 追加後 120 か月を追跡した。

| ケース | 結果 |
|---|---|
| A〜C(Iron・IG が十分、競合なし/Mine・Factory の規模違い) | MF の稼働率 1.0 が定常。月産 MS = 見込み(100)。差 < 1 |
| D(Iron 基礎 32、Factory lv10 が Iron を競合) | 約 36 か月目まで稼働率 1.0(IG 備蓄 384→240→96 を取り崩す)。以後の定常は 0.80(= 供給 S / 必要 40)、月産 MS 80 < 見込み 100 |

- 二重計上: 判定は Iron と IG を独立に比較するだけで、同じ Iron を Factory と MF が奪い合う効果は見ない。D4 の MF 優先配分が大半を解消するが、Iron 供給が必要量すれすれの場合は有限の IG 備蓄を使い切った後に S/40 まで落ちる。
- 有限備蓄の取り崩しと持続供給は区別して扱うべきで、D では前者が約 3 年続いて持続不足を隠す。
- 分類: **設計上の限界**(欠陥ではない)。将来案: Iron 供給 ≥ 40 × projected_op を追加条件にする(今回は閾値追加をしない)。

## 3. 再建後の能力不足(低雇用)

`tests/p30_003_rebuild_limits_e2e_test.rs::low_employment_rebuild_completes_recruits_but_may_not_sustain`(Oceanic の全州人口を 200 万に変更)。

- 着工: 州 9、見込み月産 11,177,015 units(約 11.2 MS/月)。
- 工場完成: 1806/02/06。
- 初回募兵: 1806/04/30(MS 34.6)。2 個目: 1807/03/30。1808/01 時点 2 個。
- MF 稼働率は 0.13〜0.17 にとどまる(雇用律速)。MS は 11.8→49.8→80.2→49.3 と推移し、0 に落ちた月は無い。

| 判定 | 結果 |
|---|---|
| 工場完成 | 達成 |
| 初回募兵 | 達成(最小常備戦力 2 の免除は能力ゲートにだけ効き、補給ゲートには効かない。募兵は備蓄が橋渡し量 ~31 MS を超えて初めて起きた) |
| 持続的な軍備復帰 | 部分的。低稼働のため復帰は遅く(2 年で 2 個)、目標戦力には届かない。ただし停止はしない |

分類: 設計上の限界(雇用に律速される生産能力)。免除の変更・新閾値・連続拡張は行っていない。

## 4. 建設キュー待ちの時系列

`rebuild_wait_timeline_is_classified`(操作日 1801/08/01、Oceanic、プレイヤーではない)。

- キュー以外の再建条件を満たした日: **1802/02/01**。それまでは `met=false` で、原因は**供給条件**(Mine の稼働が必要量に届かない。Mine の稼働率が上がるまで)であり、キューは理由ではない。
- キューを占めていた注文: Factory@9 と Factory@23(Factory 注文が交互に進み、満了後に同じ州の次レベルが再発注される)。
- 条件成立日(2/01)にはキューに空き枠があった(Factory@23 のみ)。着工(判断日): **1802/02/23**。2/01 から着工までの 22 日は月次判断の日付周期(`day % 30 == country_id % 30`)による待ち。
- 条件成立後に新しく発注された低優先注文: **なし**。
- 分類: **有限の待ち**(飢餓ではない)。優先度 2.9 が保証するのは、判断日に条件が揃っていて枠が空いていれば、優先度 3 の通常注文より先に発注される、ということまで。キューが満杯の判断日には発注されず、次の判断日まで待つ。キャンセル・予約・スケジューラは無い。

### P30-002 報告の訂正

P30-002 報告は「約 6 か月の遅れの原因は建設キューが Factory 注文で埋まっていたこと」としていた。本タスクの時系列では、1802/02/01 までは供給条件が満たされておらず、主因は供給条件(Mine の稼働の立ち上がり)だった。キュー満杯は事実だが、再建の発火を妨げた主因ではない。過去報告の本文は変更せず、ここで訂正する。

## 6. 欠陥と設計上の限界

- 欠陥: 確認できた範囲で無し。
- 設計上の限界: (a) 入力競合が必要条件止まり(D ケース)、(b) 雇用律速で復帰が遅い(低雇用)、(c) 月次判断日の周期待ちとキュー満杯時の待ち、(d) 国内資源を失った国は復帰しない。

## 7. 残課題と次の推奨

1. (任意)Iron 供給 ≥ 40 × projected_op の追加条件(有限備蓄による過大評価の抑制)。
2. 国内資源を失った国への扱い(貿易・資源獲得)は設計判断が必要で、現状は許容のまま。
3. Phase 29 の残課題と P29-002 / E1 の手動確認(PENDING)は変更なし。P27-005 と UI ウィンドウの手動確認も保留のまま。

次の推奨: Phase 30 を閉じるか、項目 1 を小さな追加検証として扱うかをユーザーが判断する。
