## 7. P24-001のどの前提が誤っていたか

P24-001§9は「州の按分負担`B`(このプロンプトでの表記に合わせると、その州への
按分結果)を一切変更しなければ、`civilian_workforce = total_wf(population) - 按分負担`
は`total_wf`の単調性からのみ決まる」と主張した。しかし按分負担自体は
`apportion_mobilized_manpower(国家全体のB, 各州の現在population)`から**毎回
再計算される派生値**であり、ある州のpopulationが変化すれば、**国家のBを一切
変えなくても**、その州および他の全州の按分負担が変化しうる。P24-001は
「単一州国家」でのみこの再按分の影響がゼロになる(按分先が1州しかないため
按分自体が自明)ことに気づかず、それを一般則として複数州へ拡張してしまった。

## 8. 複数州反例の実関数による再現

`population::mobilization::apportion_mobilized_manpower`の実装(`u128`中間計算、
`product/population_total`が基礎配分、剰余降順→`StateId`昇順のタイブレークで
端数1人ずつ配分)をそのまま追跡した。

```text
前提:
  State1: population=100, workforce_ratio=0.45(既定)
  State2: population=100, workforce_ratio=0.45(既定)
  Country: B(mobilized_manpower)=1

戦死前の按分(population_total=200, m=1):
  State1: product=100, base=100/200=0, remainder=100
  State2: product=100, base=100/200=0, remainder=100
  同率のためStateId昇順タイブレーク → State1が残り1人を獲得
  => burden[State1]=1, burden[State2]=0

State1 civilian_workforce = round(100*0.45) - 1 = 45 - 1 = 44

State1で戦死1人(population -= 1、Bは不変のまま1を維持):
  State1: population=99, State2: population=100
  population_total=199, m=1
  State1: product=99*1=99,  base=99/199=0,  remainder=99
  State2: product=100*1=100, base=100/199=0, remainder=100
  remainder降順で State2(100) > State1(99) → State2が残り1人を獲得
  => burden[State1]=0, burden[State2]=1

State1 civilian_workforce = round(99*0.45) - 0 = round(44.55) - 0 = 45 - 0 = 45
```

**State1で1人戦死したにもかかわらず、State1のcivilian_workforceは44から45へ
増加する。** プロンプトが提示した反例と完全に一致する結果を、実関数の計算規則
(`u128`中間計算・剰余降順+StateId昇順タイブレーク・`.round()`)から再現した。
原因は、戦死によるpopulation減少が「その州へ按分される負担そのもの」を
実質的に他州へ押し出してしまうためであり、Bを固定しても防げない。

## 9. 州別・国家別単調性の結果

* **州単位**: §8のとおり不成立。ある州の戦死が、按分の再計算を通じて**別の州**の
  civilian_workforceを減らす一方、**当該州自身**のcivilian_workforceを増やす
  ケースが実在する。
* **国家単位**: 上記の例で国家合計を確認する。戦死前: `44 + 45 = 89`。戦死後:
  `45 + 44 = 89`(State2は`round(100*0.45) - 1 = 44`)。**国家合計は一致して
  いる**(按分は総和B=1を過不足なく配り直しているだけのため、当然ながら
  「総和では」保存される)。つまり今回の反例は**州単位の不変条件(§3-2)のみ**を
  破り、**国家単位の不変条件(§3-3)は破っていない**。しかし州パネルは州単位の
  値を表示するため(P23-003)、プレイヤー視点では「自国のある州で兵士が死んだのに
  その州の民間労働力が増える」という直接矛盾した表示が起こり得る。国家単位だけ
  保証しても、州単位のプレイヤー体験としては受け入れられない。

## 10. 二重控除の評価

P24-001の設計(population -= C、Bは不変)は、**意図しない二重の経路**で同じ死者を
2回罰していたことを確認した。

```text
生存中: Bによって国家全体の潜在労働力からC人分が(按分経由で)控除されている
  (募兵時点で発生する既存Phase23の効果、今回変更なし)
死亡後(P24-001案): populationがC人分減るため、その人物の出身州のtotal_wf
  (潜在労働力の母数)自体もC人分(丸め次第で)小さくなる
```

前者は「今も軍にいるので働けない」という一時的な控除、後者は「この人物が
そもそも国から消えた」という母数の縮小である。この2つは意味が異なる操作
ではあるが、**同一人物1人の死亡という単一の事実に対して、civilian_workforce
の計算式へ2つの独立した経路(按分された`B`由来の控除と、`population`由来の
母数縮小)から影響を与える**設計だった。母数縮小側が(§8の反例のとおり)按分の
不安定さを通じて逆方向に効くことがあるため、これは「意図した追加の経済
ペナルティ」として正当化できるほど制御された設計ではなく、**未整理の二重控除**
と判定する。

正しい設計(§17で確定)では、この二重性を「population(=N_s、生存者数)は
死亡でのみ減る」「按分負担(=H_s、この州が現在負っている動員負担)は死亡では
一切変えない」の2つの独立したストックへ明確に分離し、**civilian_workforceの
計算式自体が死亡に対して不変になる**(単に「増えない」ではなく、厳密に
「変化しない」)ことを§17で示す。二重控除だったかどうかという問い自体が、
ストックを分離すれば意味を失う。

## 11. target_stateの実際の意味

`military::recruitment::RecruitmentQueueItem.target_state`・
`CountryData.available_manpower`の実コードを再確認した。

* `available_manpower`は`CountryData`(国家単位)のフィールドであり、**州別の
  内訳は一切存在しない**。募兵時の上限判定(`request_recruitment`の
  `country.available_manpower < def.required_manpower`)は国家合計に対して
  行われる。
* `target_state`は募兵完成後にDivisionが**出現する場所**(`current_state`の
  初期値)を決めるだけであり、「人的資源をどの州の人口から引いたか」という
  意味を実コードは一切持たない。
* AI月次募兵(`military::ai::select_ai_recruitment_state`)は自国支配下の
  首都を優先し、次点で人口最大の自国支配州を選ぶ。これは「どこにDivisionを
  配置するか」の決定であり、「どの州の住民を徴兵するか」の決定ではない。

**結論: `target_state`を出身州(人口の由来)として再利用してはならない。**
これはP24-001が犯していたもう一つの誤り(§7を参照するまでもなく§11単独でも
致命的)であり、`target_state`は「配置州」という別概念として維持し、人口の
由来を表す新しい概念とは明確に分離する必要がある。この分離自体は§17の設計で
反映済み(H_sは募兵時に「どの州へ帰属させるか」を新たに決定する必要があり、
`target_state`をそのまま転用しない)。

ただし、将来州別軍事人口会計(案C、§13)を実装する際の指針として、次を

出さない(§17の保留案では発生しないため未決のまま、案Cを実装するタスクで

## 13. population不足時の処理

§17の保留案では発生しない(population書き込み自体がない)。将来案Cを実装する
際の制約として記録する: `N_s -= C_s`と`D_s += C_s`を厳密に対になる操作にすれば、
`N_s`が不足する場面(その州の生存者数を超える損失)は理論上起こりにくくなる
(D_sへの計上はN_sから移動した分だけであるべきで、N_s以上をD_sへ計上する
経路を作らなければ、不足自体が構造的に発生しない)。ただし「その州出身の
Divisionが、州の現在population以上のmanpowerを保持している」という初期条件
(例: 州の人口が戦争で先に減っていた場合)をどう扱うかは未決のまま残る。
`saturating_sub`で黙って捨てる案は、プロンプトの指示どおり採用しない
(採用する場合は残余の行き先を決定的に定義する必要があるが、案C自体が
将来タスクのため今回は結論を出さない)。

## 15. workforce丸め方式不一致の扱い

P24-001が発見した`StateData::total_workforce()`(切り捨て)と`population::
update::calculate_workforce()`(四捨五入)の不一致を再確認した。両者は概念上
同じ「population × workforce_ratio」だが、前者はP23-004の`E/P`比率
(`economic_workforce_ratio`)の分母、後者は`civilian_workforce`(P23-003)の
算出元として、それぞれ別の実運用コードパスで使われている。

本タスクでは、この不一致の**統一自体を実施しない**(§16の対象外どおり)。ただし
§17でP24-002として正式に提案する。理由: この不一致は人口連動の可否と無関係に
独立して修正可能であり、動員0の場合の既存挙動(P23-004が固定した`E/P`の数値)を
変えない移行が可能かどうかを検証すること自体が、その1個のタスクとして十分な
大きさを持つ。丸め方式の統一を人口連動より先に行うべきかという問いには、
**先に行うべき**と回答する(人口連動の会計を将来設計する際、どちらの丸めが
「正規」かが定まっていないと、州別台帳の数値がさらに不安定になるため)。

## 17. 採用する訂正設計

**P24-002では、戦死とpopulationの接続を実装しない。Phase 23の会計
(A・B・L・K・X、`compute_manpower_ledger`、`civilian_workforce`、
`apportion_mobilized_manpower`)を一切変更せず、そのまま維持する。population
は引き続き月次成長でのみ増加し、減少させる経路を追加しない。**

この保留が正しい選択であることの根拠(案Cの数式による証明、将来の接続方式):

```text
将来案C(今回は実装しない、設計としてのみ記録):
  N_s = 州の現在生存population(既存のstate.populationをそのまま使う、新規ストック不要)
  D_s = その州に帰属する累積恒久軍事損失(新規ストック)
  H_s = その州が現在負っている動員負担(新規ストック、国家Bの州別内訳)

  募兵R(州sへ帰属決定): H_s += R
  戦死C(州sの生存兵員が損耗): N_s -= C, D_s += C, H_s は不変
  補充Q(州sへ帰属するDivisionへ): H_s += Q
  復員R(州sへ帰属するDivisionの生存者): H_s -= R

  civilian_workforce_s = workforce(N_s + D_s) - H_s
```

戦死イベントでは`N_s + D_s`が定義上不変(`N_s`から出た分だけ`D_s`へ入る)であり、
`H_s`も戦死では変更しないため、**civilian_workforce_sは戦死に対して厳密に
不変**(増えないだけでなく、そもそも変化しない)。§8の反例(按分の不安定さ)は、
`H_s`を「population比で毎月再按分する派生値」ではなく「募兵・補充・復員
イベントで直接加減算する明示的なストック」にすることで、構造的に発生しなく
なる——按分計算自体を経由しないため、population変化がH_sへ波及する経路が
存在しない。これがP24-001案とcase Cの本質的な違いである。

案Cは正しいが、次の未決事項が残るため今回のP24-002には含めない(§21の
最小実装範囲を参照):

* 募兵時、国家の統一`available_manpower`プールから、どの州の`H_s`へ
  帰属させるかの決定方式(§11で`target_state`は使えないと確認済み)。
* 州所有権変更時の`N_s`/`D_s`/`H_s`の扱いの正式規約(§12で既存規約の流用は
  提案したが未実装)。
* population不足時の残余処理(§13で構造的に起こりにくいことは示したが、
  初期条件次第の残存ケースは未決)。
* Save V2への移行方式(§20)。

## 18. 却下案と理由

* **案B(P24-001の原案)**: §8(複数州での逆説再現)、§10(二重控除)、
  §11(target_stateの誤用)のいずれか単独でも致命的であり、3つとも実証された
  ため却下する。
* **案E(国家人口のみ、州へ割り当てない)**: 既存の州パネル・州単位の
  `civilian_workforce`表示(P23-003)と矛盾する二重の真実源(国家レベルの
  人口ストックと州レベルのpopulationが別々に存在する)を生むため、プロンプトの
  指示どおり原則却下する。

## 20. 人的資源上限の意味

**変更しない。** `compute_manpower_cap(population) = population × 10%`は
引き続き「所有population(州単位ではなく国家合計)から算出される、平時の動員
余地の目安」というsoft targetとして扱う。`A+B<=cap`等は今回も強制しない
(プロンプト§11の分類で言えば、現行コードでの実際の使用箇所は「月次回復の

であり、hard capとしては一度も使われていないことを再確認した)。population
連動を保留するため、今回この値の意味を変更する必要自体が生じない。

## 21. Save V1／V2の判断

**今回はV1を完全に維持する。新規フィールドを一切追加しない。**

構文互換性・意味的互換性のいずれについても、「何も追加しない」ことで自明に
両方を満たす(§14で確認したとおり)。これは「V1を維持できるから」という
理由で不完全な設計を選んだのではなく、「今回は何も実装しないため、互換性の
問題自体が発生しない」という消極的だが正直な結論である。

**将来案C(§17)を実装する際は、Save V2が実質的に必要になる**と予測する
(`H_s`/`D_s`という新しい州別永続ストックは、既存フィールドから再導出できない
新規情報であり、`#[serde(default)]`による黙示的な意味づけ[例: 全州0スタート]
では、旧セーブロード時に「これまでの累積損失・動員実績が一律0からスタートする」
という不透明な意味変更を招くため、V1のまま押し込むべきではない)。ただし
これは将来タスクでの判断であり、本タスクでは正式決定しない。
