## 4. 移動命令と日次処理(旧経路から引き継いだ挙動と、実コードでの確認)
### 4.1 命令 `issue_move_order`(旧 `start_or_maintain_movement` の契約を保つ)
| 条件 | 結果 |
|---|---|
| 師団が存在しない | 拒否 `UnknownDivision` |
| 目的地が未知の `ProvinceId`(水域・範囲外の陸のセルには ID が無い) | 拒否 `UnknownProvince` |
| Idle で現在地、または移動中の同じ目的地 | **no-op**(`AlreadyThere` / `AlreadyMoving`。状態を一切変更しない。旧と同じく、移動中は「同じ目的地」だけで判定) |
| 目的地が所属国の支配でない(他国の支配 / 支配国なし) | 拒否 `DestinationNotPassable { controller: Some(c) / None }` |
| 自国支配のプロヴィンスだけでは経路が無い | 拒否 `NoPath` |
| 経路が確定 | **受理**。`destination`/`path`/`target=None`/`progress=0`/`Moving` を**まとめて**適用。**現在地は動かさない** |
- 拒否しても、師団の既存の命令・経路・進捗は保たれる(テストで全師団の状態の等価を確認)。
- 経路: 辺の費用 1、**同費用の候補は `ProvinceId` 昇順**(各階層を昇順に展開し最初に見つけた親を採る。旧 `find_path` の `(費用, ID)` 順のヒープと同じ結果)。隣接は `ProvinceGraph`(六角形の辺の接触から導出)。通れるのは所属国の支配するプロヴィンスだけ。河川は費用にも可否にも加えない(河川つきの地図で 2 ホップ=10 日のままをテスト)。範囲外の陸・水域は ID が無いので通れない。
### 4.2 日次 `advance_day`(`MapDivisionId` 昇順。旧 `MilitaryAction` の「経路検証 → 移動」)
1. 経路の事前検証(旧 `validate_and_stop_invalid_movements`): 次の移動先(`target`)が通れなくなっていれば**進入前に停止**(Idle、現在地のまま、命令・経路・進捗を消す)。残りの経路に通れない所があれば、経路と目的地を切って**現在のホップだけ続ける**。
2. 移動(旧 `process_movement`): `target` が空なら経路の先頭を取り、空なら到着(Idle)。次の移動先が通れなければ停止。進捗に `1/日数` を加え、**1.0 に達した日に現在地を更新**。経路が残れば次のホップへ、無ければ Idle。
- 命令と位置は実行時状態で、保存しない(M8 まで)。
### 4.3 初期配置の検証(シナリオ。問題はすべて集めて code で報告)
`duplicate-country-label` / `duplicate-country-id` / `unresolved-country` / `duplicate-state-owner` / `unknown-state` / `duplicate-override` / `unknown-province` / `duplicate-division` / `initial-position-not-controlled`(初期位置の支配が所属国と不一致)/ `invalid-speed` / `invalid-base-days`(非有限・非正)。形式の失敗(読めない・RON として不正・未知のフィールド・必須項目の欠落・非対応の版)は別に区別する。

## 6. 旧経路との比較(小規模 fixture。新旧IDの対応表を明示)
`tests/p32_034_map_movement_test.rs` の `one_hop_and_multi_hop_arrival_days_match_the_old_path…` と `equal_cost_path_choice_matches_the_old_find_path…`。旧は **実際に旧型で実行**(旧 `StateRegistry` の鎖、旧 `Division`・`DivisionDefinition`、`start_or_maintain_movement`・`validate_and_stop_invalid_movements`・`process_movement` を毎日呼ぶ)。対応表: 旧 `StateId i` ↔ 新 `ProvinceId 100+3i`(順序を保つ)。同じ隣接・費用・基準日数 5.0・補給係数 1.0。
- 速度 {1.0, 2.0, 0.5, 10.0, 1.7} × ホップ数 {1, 2, 4} × 60 日で、**各日の位置・状態(Idle/Moving)・進捗(f32 の値まで)・到着日が完全に一致**(経路も一致)。具体値: 速度 1.0 の 1ホップ=5日目、4ホップ=20日目。
- 同費用の経路(菱形の4プロヴィンス): 旧 `find_path` と新が、順序を保つ対応表のもとで同じ経路(ID の小さい側)を選ぶ。

**挙動の差と仕様上の扱い**(今回の比較で見つかった差、および設計上の意図した差):
| 差 | 原因 | 仕様上の扱い |
|---|---|---|
| 同費用の経路選択は**各モデルの ID 昇順**に従う。**対応表が順序を保たなければ**、旧と新で選ぶ経路が変わる(テストで、旧の番号を A<B<C にすると旧は B を選び、新は ProvinceId の小さい C を選ぶことを確認) | tie-break は旧が `StateId`、新が `ProvinceId` の昇順 | **意図した差**。新経路の選択は新 ID だけで決まり、旧の採番とは独立。旧新の比較 fixture は順序を保つ対応表を使う |
| 隣接: 旧は手書きの**有向**リスト、新は六角形の辺の接触から導く**無向**(対称) | 設計(P32-029 / M5) | 意図した差 |
| 通行: 旧は自陣営+敵対国の支配(`allowed`/`hostile`)、新は M6-a では所属国の支配だけ | 戦争関係が未接続(M6-b) | M6-b で敵対国の支配地への侵入を追加する |
| 補給係数: 旧は `max(supply_ratio, 0.5)`、新は 1.0 固定 | 補給計画に未接続(M6-d) | M6-d で接続する |
| 移動の数値の差は**見つからなかった**(日数・進捗・到着日) | 旧と同じ f32 の式 | — |
- テストしていない旧の挙動: 移動中に**現在地への命令**を出すと、旧は空の経路で Moving にし(次の日に Idle)、現在のホップを取り消す。新も同じ実装(`find_land_path` は `start==end` で空の経路を返す)だが、このケースを専用のテストでは確認していない。
