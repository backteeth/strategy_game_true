## 集計項目と導出方法(地理のみ)
`derive_world_geo(&WorldModel, &HexMap)`: まず M0 の Authoring 検証を行い、Error があれば**部分集計を作らず `Err`**(存在しないセル・水域を指すプロヴィンスを黙って無視しない)。
ステートごと(`MapStateId` 昇順): 所属プロヴィンス数、地形別・気候別・植生別セル数(`Terrain::ALL`/`Climate::ALL`/`Vegetation::ALL` の順)。属性は地理データ(`HexMap`)を参照し、所属ファイルへは保存しない。`none`/`unclassified`、`plateau`/`highland` は別項目。各内訳の合計=所属プロヴィンス数(`is_consistent`)。集計対象は所属済みプロヴィンスのみで、未割当・検証範囲外・水域は混ざらず、架空のステートも作らない。プロヴィンス数は面積ではない(km² 等へ換算しない)。空ステート等は M0 の検証規則のまま(新しい例外なし)。

## 隣接の導出、共有辺と河川辺の正規化
- 隣接 = 六角形の**辺を共有**する、双方が所属済みの陸プロヴィンスで、所属ステートが異なるもの。六角格子では頂点を共有するセルは必ず辺も共有するため「頂点だけの接触」は存在しない(距離 2 以上は隣接でない。テストで確認)。海・湖・未割当・範囲外を挟んだ関係は隣接にしない。河川は隣接を切断しない(渡河可否・移動コストは未決のまま)。
- 共有辺は P32-005 の `compute_boundaries` の `StateBorder`(整数座標で正規化済み。`(q,r)` が辞書順で小さい側から 1 辺 1 件)をそのまま使い、無向の組 `(a < b)` ごとに数える。同一ステート内部の辺は含まれない。AとBは 1 件だけ保持(対称、`adjacency_between(a,b) == adjacency_between(b,a)`)。
- 河川辺: `HexMap::river_edges`(両側から記録された同じ河川を統合済みの正規形 `(q,r,direction)`、(q,r) が小さい側)と、共有辺の同じ正規形キーを突き合わせるため二重計上されない。共有辺上の河川だけを数え(`shared_river_edges ≤ shared_edges`)、内部の河川・未割当や水域との辺の河川は含めない。共有辺数・河川辺数は「数」であり、境界長(km)ではない。

## Partialと未割当の扱い(情報の完全性)
`Completeness { coverage, unassigned_provinces, out_of_scope_land_cells }`、`is_complete()` = World かつ未割当 0 かつ表に無い陸 0。隣接の問い合わせは `Found(..)` または `NotRecorded { complete }` で、**不完全な結果では「記録なし=存在しない」と読めない**(`complete: false`)。World でも未割当が残れば不完全、Partial は全員所属でも不完全(テスト済み)。確認できた共有辺は不完全でも増減させない。結果は今回読み込んだ地理と所属データに対するもので、将来の正式な世界設定の完成を意味しない。結果は `Serialize` を持たず、保存・RON への書き戻しはしない(再生成可能)。`is_current_for(model, map)` で、地理識別情報または所属が変わった場合に古い結果を検出できる(プレビューは再入場のたびに再読み込み・再導出し、前回の結果を引き継がない)。
