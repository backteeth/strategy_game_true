## 既存施設との区別
`BuildingType` の10種はすべてステート単位の経済施設で、港・要塞・駅に当たる型は無いことをコードで確認。位置施設は別型(`LocationFacilityKind { Port, Fortress, RailwayStation }`)で、`BuildingType`/`buildings.ron`には追加していない(雇用・生産・維持費・建設AIへ混入しない。テストで確認)。ステートの工場・農場等はプロヴィンスへ移していない。

## 型と入力形式
- `LocationFacilityId(u32)`: ファイルに明記された安定ID(読み込み時に生成せず、配列順で変わらない)。`ProvinceId`/`MapStateId`/国家IDとは別型で相互変換なし。
- `LocationFacilityDef { id, kind, province }`: 施設の個別IDと所在地を区別。規模・レベル・効果・費用は持たない(意味が未決のため追加していない)。
- ファイル: `format_version: 1`(非対応は明確に失敗)、`scope: World|Partial`、`facilities`、`confirmed_empty`。
- 同一プロヴィンスの複数施設・同種の重複・スロット数は未決のため、**拒否も許可の確定もせず全件保持**。

## 正本と導出
- 正本は施設定義(所在地=ProvinceId)。`LocationFacilityRegistry`の施設ID索引・所在地索引は読み込み時の導出。
- ステート別の施設は**保存せず**、問い合わせごとに「所在地 → 渡された`WorldModel`の現在の所属」から導出(`facilities_in_state`)。ステート側に別コピーが無いため、所属変更後に古い索引が残らない(テストで確認)。所属のない施設は`unassigned_facilities`として保持し、架空のステートへは入れない。国家所有・占領者は扱わない。

## 未設定と施設なし
資源入力(P32-009)と同じ方式。施設あり=設定済み、`confirmed_empty`=設定済みで施設なし(明示)、どちらでもない=未設定(`ProvinceFacilitySetup`・`StateFacilitySetup`)。`scope: World`で未設定が残ると入力エラー。施設ありと施設なしの矛盾はエラー。検証用は`Partial`で、全世界の配置完了を意味しない(CLIにも明記)。

## 地理条件の確認
`water_adjacency(map, cell)`が6近傍の海・湖・範囲外(地図に無いセル)を数える。河川は含めない。結果は地理上の事実で、建設可否の判定ではない: 水域に接さない港も入力としては受理され、湖の港・河港・海域接続・駅の鉄道網・要塞の防御方向・建設条件/上限は未決のまま。実地図に湖が無いため、湖・負のq・地図境界は小さな合成fixtureで確認(地理JSONは変更していない)。
