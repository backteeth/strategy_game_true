## 3. 採用した仕様
### 3.1 交戦関係と進入(U1・U6)
- **交戦関係は検証用 RON の `wars` に国家ラベルの組で明示する**(双方向。順序は無意味)。旧 `WarRegistry`・経済シナリオ・補給検証用の入力からは推定しない。検証: 未知の国家(`unresolved-country`)、同一国家の組(`self-war`)、**逆順を含む重複**(`duplicate-war`)、戦闘能力の不正(`invalid-combat`)を区別して報告。`wars` を書かない M6-a のシナリオは従来どおり読み込めて動く(テスト・CLI で確認)。
- 通れるのは**自国の支配地と、交戦国の支配地**(旧 `find_path` の `allowed`/`hostile`)。命令の受付と日次の両方で、到着先の**現在の**支配国と交戦関係を確認する。区別: 自国支配(従来どおり)/ 交戦国の支配(進入を試みられる)/ **非交戦国の支配**(`DestinationNotPassable { controller: Some }`)/ **支配国なし**(`controller: None`)/ 未知のID(`UnknownProvince`)。次の移動先が通れなくなったら、**そのプロヴィンスへ到着する前に停止**(`Stopped`)。
- **敵支配地に着いたときの残りの経路(M6-b 単体)**: 師団は到着したプロヴィンスに入り(現在地を更新)、**残りの経路と目的地を破棄して止まる**。占領が成立したものとして敵領の奥へ自動で進まない。続きの移動は、M6-c で実効支配が更新された後に改めて命令する。(命令の受付は、敵支配地を通る経路を許す。旧と同じ。)
- 戦闘の場所は **`ProvinceId`**。参加するのはその地点にいる師団だけで、**同じステート内の別プロヴィンスの師団は入れない**(テスト: 同じステートの隣接プロヴィンスにいる敵師団は参加しない)。1地点で進行中の戦闘は1つだけ。

### 3.2 戦闘の開始・合流(旧 `process_division_arrival`・`find_enemy_divisions_in_state`)
- 敵師団がいる地点では戦闘を開始する。**防御側は、その地点にいる攻撃側の国と交戦中の国の師団の全員**(`MapDivisionId` 昇順。旧と同じ)で、**防御側の国は先頭の師団の所属国**(旧と同じ)。攻撃側の出撃元(直前のホップの出発地)を記録する。
- 同地点で進行中の戦闘があれば、**攻撃側の国の師団だけが合流**する(`MapDivisionId` 昇順で保持、重複登録しない)。
- **合流条件を満たさない師団の扱い**(第三国・防御側の国): 敵支配地への進入時に、別の国が攻撃側の戦闘が進行中なら、**進入前に止める**(`StoppedBefore { reason: ContestedByOthers }`。位置は変えず、Idle、命令なし)。旧は到着先へ入ってから待機させ、戦闘に参加しない師団が戦場に居座る(§5 の差 3)。防御側の国の師団が自国支配の戦闘地点へ入る場合は、旧と同じく通常の移動として入れるが戦闘には合流しない(後続の課題)。
- 師団が同時に複数の戦闘に所属したり、同じ戦闘へ重複登録されたりしない(不変条件を、全テストの各日で検査: 参加者は昇順・重複なし・`Fighting` で戦闘IDが一致・1地点に進行中の戦闘は1つ・戦闘中の師団に命令なし)。
- **戦闘中・退却中の命令受付**: 戦闘に参加中(`Fighting`)の師団は、**現在地への命令を含めてすべて拒否**(`DivisionInCombat`。状態不変)。旧は API が確認せず UI/AI(呼び出し側)が `Fighting` を確認する。新は API に持たせた(§5 の差 4)。**退却中という状態は持たない**: 旧の `Retreating` は本番で一度も設定されず、撤退は同じ処理の中で即座に完了する。したがって「退却中の命令」は存在せず、退却後の師団は退却先で Idle として通常どおり命令を受け付ける。通常移動の冪等性(現在地・移動中の同じ目的地は no-op)と、拒否時の状態保持は、戦争関係がある条件でもテストで確認した。

### 3.3 日次処理の順序(安定した ID 順。`advance_day(&graph)`)
| # | 処理 | 順序 | 旧経路 |
|---|---|---|---|
| 1 | 経路の事前検証(次の移動先が通れなければ進入前に停止、残りの経路に通れない所があれば経路を切る) | `MapDivisionId` 昇順 | `validate_and_stop_invalid_movements` |
| 2 | **移動と接触**(1ホップの日数は旧の式。敵支配地への到着で、戦闘の開始・合流・守備隊なし・進入前の停止) | `MapDivisionId` 昇順 | `process_movement` + `process_division_arrival` |
| 3 | 戦闘の進行(旧の計算で損耗を適用。ゼロ損害の戦闘を記録) | `MapBattleId` 昇順 | `process_daily_battles`(昇順) |
| 4 | **終了処理**(脱落者の退却・撃破、勝敗の確定、結果の発行) | `MapBattleId` 昇順 | `resolve_finished_battles`(**旧は HashMap の順序**。差 6) |
| 5 | 終了した戦闘の除去 | — | `cleanup_finished_battles` |
| 6 | 組織率の回復(Idle・自国支配の地点にいる師団) | `MapDivisionId` 昇順 | `process_org_recovery` |
当日に始まった戦闘は同じ日に進行・終了処理まで進む(旧と同じ)。新しい戦闘のIDは、同じ日に始まる場合は到着した師団の ID 昇順。

### 3.4 勝敗・退却(旧 `resolve_finished_battles`・`find_retreat_destination`・`attacker_retreat_destination`)
- 脱落(組織率 0)した師団は、退却先があれば退却(追加の人員損失・比例する装備損失)、退路がない・人員が尽きる場合は**撃破**(装備は全損、師団は除去)。どちらかの陣営の参加者がいなくなれば戦闘が終わる。
- **攻撃側の退路**(出撃元と隣接退路を区別): ①出撃元が有効(**自国支配で、進行中の戦闘が無い**)ならそこ。②無効なら、戦闘地点の隣接で**自国支配かつ戦闘中でない最小の `ProvinceId`**。③なければ撃破。**防御側の退路**: 戦闘地点の隣接で、その師団の国の支配かつ戦闘中でない最小の `ProvinceId`。なければ撃破。「戦闘中でない」は**進行中の戦闘**だけを見る(同じ日に先に終わった戦闘の地点は使える。差 6 の帰結で、テストで固定)。
- 旧経路を確認して採用した扱い(テストで固定): 出撃元が使えない+代替もない → 撃破(旧と一致: `old_comparison_the_attacker_origin_is_lost_and_there_is_no_other_retreat…`)。出撃元が使えない+代替がある → 最小の代替へ(旧と一致)。防御側に退路がない → 撃破、攻撃側勝利(旧と一致)。その日どちらの陣営も人員損失が 0 → **防御側勝利**、攻撃側全員を撤退(旧 P27-007。旧と一致)。
- 勝敗: 防御側がいなくなれば攻撃側勝利、攻撃側がいなくなれば防御側勝利、両方いなくなれば防御側勝利(支配は変わらない。旧と同じ)。

### 3.5 M6-c へ渡す結果(`MoveEvent::ControlClaim`)
- **守備隊がいない進入**と**攻撃側の勝利**で、**実効支配は更新せず**、更新要求を**1回だけ**発行する。内容: 対象 `ProvinceId`、攻撃国(`claimant`)、直前の支配国、**理由**(`Undefended` / `AttackerWonBattle(戦闘ID)`)、関わった師団(昇順)。戦闘の終了は別に `BattleFinished`(結果・理由 `DefenderGone`/`AttackerGone`/`BothGone`/`ZeroDamage`)で出る。
- **支配国が更新される前の師団の状態**: 対象プロヴィンスにいて **Idle**、命令なし(経路・目的地・次の移動先は破棄、進捗 0)、戦闘IDなし。戦闘は終了した日に除去される。
- **翌日に同じ結果を繰り返さない**: 接触は「移動中の師団が到着したとき」だけ起き、戦闘は終了した日に除去されるので、支配が更新されなくても要求は再発行されない(テスト: 守備隊なし・攻撃側勝利とも、40日・20日進めて要求は1件だけ)。

## 5. 旧経路との比較と、挙動の差
旧は **`handle_daily_military`(旧の日次処理そのもの)を最小の Bevy App で実際に動かし**、同じ条件の新経路と各日の状態を比べた(`tests/p32_035_map_battle_test.rs` の `old_comparison_*` 9件)。新旧IDの対応表: 旧 `StateId i` ↔ 新 `ProvinceId 100+10i`、旧 `DivisionId n` ↔ 新 `MapDivisionId n`。隣接はテスト内で独立に六角形の規則から作った。比べたのは各日の全師団の (位置・状態・人員・組織率・装備・目的地・次の移動先・経路・進捗) と、進行中の戦闘の (地点・攻撃側・防御側)、各州の支配国。
- **一致した条件**(各日の全項目が一致): 攻撃側の勝利(防御側の退却)/ 防御側の勝利(攻撃側が出撃元へ撤退し、その後の組織率回復)/ 防御側に退路がなく撃破 / 出撃元が使えず退路もなく撃破 / 出撃元が使えず最小の代替へ撤退(星形)/ 増援の合流 / 両陣営ゼロ損害 / 通常の移動と「移動中に現在地へ命令」(M6-a で専用テストがなかった項目。旧も新も、空の経路で Moving にして現在のホップを取り消し、翌日 Idle)。
- 占領の日の扱い: 旧は戦闘の終了処理の中で支配国を変えるが、新は要求を返すだけ。比較ハーネスは**同じ日に要求を新側の支配へ適用して揃え**、旧では支配の変更直後の組織率回復が同日に +5 先に効く分だけを補正し、占領の日で比較を止める(以後は旧だけが支配を変えた状態の回復が先行して軌跡が意図してずれる)。

**挙動の差と仕様上の扱い**

## 6. 戦闘計算の再利用の境界(今回の検証に必要な範囲と後続の課題)
- 旧の計算関数(`military::combat_calc`・`military::equipment`)は、旧 `Division`(位置・命令・`StateId` を含む)と `MilitaryRegistry`(補給充足率)を受け取る。新経路の師団は旧型へ変換しない方針(M6-a)なので、**隔離アダプタ `world::legacy_combat` だけが旧に依存**し、計算の間だけ**戦闘能力の値から旧 `Division` の一時的な値**を作って旧の関数を呼び、結果を `MapDivisionId` に戻す(一時的な ID は旧のレジストリ・戦闘・状態へ渡さない。テストで依存の範囲を検査)。
