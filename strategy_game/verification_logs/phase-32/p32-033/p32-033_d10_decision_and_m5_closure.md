## 2. D10 の決定(ユーザー指示により採用)
**D10(補給連結性の計算単位)**: **プロヴィンスグラフ上で到達判定し、区画の所属に基づいて `MapStateId` 単位の要約を導出する。** ステート隣接グラフ上での再探索はしない。元計画 §11 の推奨案(P グラフ BFS)と一致し、代替案(S グラフで計算)は採らない。

### 2.1 根拠
| 論点 | 根拠(実装・記録) |
|---|---|
| ステート内部の分断を表現できる | P32-031 `a_state_split_inside_is_partial_never_full`: 4件のステートで内部の1件が通行不可のとき、到達2件・不能2件で「一部到達」。通行条件を変えると全域に変わる。実データでも、ステート20・22だけを許可した条件(A)でステート22 は「不明」、未所属3件を許可した条件(B)で「全域」と、**ステートの内側の経路の有無**が結果を分けた。ステート単位のグラフだけでは、この区別(ステート内部の分断・未所属プロヴィンスを橋渡しにする経路)が表せない |
| 旧小規模ケースとの一致範囲 | P32-031 の `old_small_case_*`(旧 `connected_states_from_capital` と同じ隣接・起点・通行条件を、新旧IDの対応表つき fixture で比較): **連結(直線)・分断(海)・通行禁止(他国支配)・環+尾の4ケースで到達集合が一致**。同時に、新グラフの辺を対応表で旧IDへ変換した集合が手書きの旧の辺と一致することも確認(同じ隣接関係を表している)。fixture は「1ステート=1プロヴィンス」で、旧のステート単位と新のプロヴィンス単位が一致する範囲に限る |
| 意図した差 | ①首都(起点)が通行不可のとき、旧は空集合を返し、新は入力不正(`NotPassable`)にする(黙って通行可能にしない)。②旧は州の手書きの**有向**隣接をたどり、新は六角形の辺の接触から導く**無向**の隣接(対称)。③新は「不明」(範囲外の陸を通る経路があり得る)を区別する(旧には無い)。④旧ステート単位では表せない「ステート内部の分断」は新だけが表現する |
| 規模と計測条件 | P32-031: 現在の地図の陸セル 35,221 を **1陸セル=1プロヴィンス**とした測定専用のグラフ(メモリ上のみ。**正式な全世界の区画ではない**)。ノード 35,221 / 辺 99,948 / 連結成分 109(最大 18,171)。ステートは 10×10 セルの格子 573 件+未所属 364 件。探索主体 3 / 30 / 100(起点・通行集合は決定的に生成。正式な国境ではない)。release、単一スレッド、1条件 3 試行、1台(i7-12700F)、他プロセス共存、**未最適化**。1ゲーム日相当(準備→到達判定→ステート集約→解放)の中央値: 高負荷(各主体が約 17,200 件に到達)で 3 主体 9.2 ms / 30 主体 90.6 ms / 100 主体 282.2 ms、通行範囲が分かれる条件で 5.2 / 27.7 / 80.2 ms。1主体の到達判定は約 0.4〜1.9 ms。静的グラフ構築は約 29 ms(毎日の費用ではない)。全条件・全試行が上限 120 秒の内で完了、結果は試行間で一致 |
| 計測の限界(結論の前提) | 1台・3試行で、実行間で約 5〜15% の揺れがあった。1陸セル=1プロヴィンスの理想化で、実際の全世界の区画とは節点数・辺数が異なり得る。メモリのピークは未測定。ゲーム本体(描画・経済・AI)と並走した場合は未測定。準備は「毎日、全主体の通行集合を作り直す」最悪側。**本体の1日の時間予算は決まっていない** |

### 2.2 再計算方針(D10 に付随。確定する範囲と M6 へ送る範囲)
- **第一候補(採用)**: 補給源・通行条件・所属など、入力が変化した主体だけを再計算する。P32-031 の測定では、再計算の費用は変化した主体数にほぼ比例し(1主体あたり 約 0.8〜2.8 ms、未最適化)、毎日全主体を再計算する費用(最悪側 100 主体で約 0.28 秒)より小さくできる見込みである。
- **M6 で実際の利用箇所と計測条件を踏まえて検討する(今回は決めない)**: 日次の時間予算、キャッシュの実装(保持する単位・無効化の規則・保存しない方針)、再計算の実行順(日次の更新順の中での位置)。最適化の候補(通行条件のビット列化、`Reach` の複製の削減、集約の差分化)も、必要が示された段階で扱う。
