## 2. 旧経路の実際(型・関数・更新順。すべて今回コードを読んで確認)
### 2.1 師団と位置(`military/data.rs`)
`Division`: `id: DivisionId`、`owner: CountryId`、**`current_state: StateId`**、`destination: Option<StateId>`、**`current_path: Vec<StateId>`**、`target_state: Option<StateId>`(今向かっている1ホップ先)、`movement_progress: f32`、`status: DivisionStatus`(`Idle`/`Moving`/`Fighting`/`Retreating`/`Occupying`/`Disbanding`/`Destroyed`)、`supply_ratio`、`combat_id: Option<BattleId>` ほか。`MilitaryRegistry.divisions: HashMap<DivisionId, Division>`、補給の充足率は別の補助 map(`division_supply_fulfillment`)。**`Division` は全フィールド列挙のリテラルで数十箇所に直接構築され、変更禁止のテストを含む**(データ型の注記より)。したがってフィールド追加・型変更は波及が大きい。

### 2.2 移動
| 関数(ファイル) | 内容 |
|---|---|
| `start_or_maintain_movement`(`movement.rs`) | 移動開始・維持の**冪等API**(P27-004)。同じ目的地へ移動中・既に到着済みなら no-op(`find_path` も再実行しない)。それ以外は `find_path` を実行し、成功時のみ `destination`/`current_path`/`target_state=None`/`movement_progress=0`/`status=Moving` を**原子的に**更新。失敗時は何も変更しない。プレイヤー手動・Defend AI・Offensive AI の3経路が使う |
| `find_path`(`pathfinding.rs`) | ダイクストラ。`StateData.neighbors`(手書きの有向リスト)を走査。**辺の費用は常に 1**(`calculate_step_cost`)。**通行は隣接先の `controller()` が `allowed_countries`(自陣営)または `hostile_countries` に含まれる州だけ**(終点にも同じ条件)。同費用の tie-break は `(cost, StateId)`(ヒープ順)で決定的 |
| `process_movement`(`movement.rs`) | `DivisionId` 昇順で処理。`Moving` だけを対象(`Fighting`/`Retreating` は動かない)。`target_state` が空なら `current_path` の先頭を取り、空なら到着(Idle)。移動先の `controller()` が自国でも交戦中の敵でもなければ**停止**(通過不可)。**1ホップの日数 = `max(1, base_days(5.0) × step_cost / (def_speed × supply_mod))`、`supply_mod = max(division.supply_ratio, 0.5)`**。進捗が 1.0 に達したら `current_state` を更新。到着先が自国支配なら(最終目的地で)Idle、敵支配なら `process_division_arrival` |
| `validate_and_stop_invalid_movements` | 日の初めに、戦争終了などで無効になった移動を停止(`target_state` の通過可否、残りの経路の検証)。`divisions.values_mut()` を使う(HashMap 順だが、各師団を独立に処理するので結果は順序に依存しない) |

### 2.3 侵攻・戦闘・占領
| 項目 | 実際の挙動 |
|---|---|
| 到着処理(`invasion::process_division_arrival`) | 到着先が自国支配 → 何もしない。交戦中でない国の支配地 → 停止。**同じ州で進行中の戦闘**があれば、自軍が攻撃側なら合流、そうでなければ停止。敵師団がいれば**戦闘開始**(その州の敵師団全員が防御側)。**敵師団がいなければ `occupy_state` で即座に占領** |
| 戦闘(`military/battle.rs`、`update.rs`) | `Battle.state_id: StateId` が戦闘の場所。`attacker_origins: HashMap<DivisionId, StateId>`(攻撃側の出撃元=敗北時の退路)。`process_daily_battles`(`BattleId` 昇順)→ `resolve_finished_battles`。**攻撃側勝利で `occupy_state`**、敗北側の退路は `find_retreat_destination`(自国支配の隣接陸地で、戦闘中でない州のうち `StateId` 昇順最小) |
| **占領の実体(重要)** | 本番経路の占領は **`occupy_state` が `controller_country = Some(新支配国)` を書くだけ**(`invasion.rs`)。**占領進捗(`occupation_progress`)も `war_id` も書かない**。`war/occupation.rs::process_occupation`(師団1個あたり +5.0/日、100 で支配国交代 = 20日で占領)は**本番のシステムから呼ばれず、テストからだけ呼ばれる**(`war/peace.rs` の P28-008 の注記と、呼び出し箇所の検索で確認)。元計画の「現行 +5.0/日・20日占領」(D8)は、本番では動いていない関数の数値である |
| 戦争点数・降伏 | `war::war_score::process_war_score` が `controller_country` から占領ステートを更新(`WarResolution` Set。講和・降伏判定の前) |
| 和平・領土移転 | `war/peace.rs` が `state::ownership`(原子的な共通 API)で所有を移転。占領元 War は `war_id` に依存せず、`owner`・`controller` の組と参加国で判定する(P28-008) |

### 2.4 日次の更新順(`app/time.rs` の `DailySimulationSet`、`military/mod.rs`)
`TimeUpdate → Economy → Research → Diplomacy → CountryAi → WarPreparation → MilitaryAi → FrontlineOrders → MilitaryAction → WarResolution → UiUpdate`(`.chain()`)。
- **`Economy` Set 内**: `process_daily_military_supply_consumption`(`handle_monthly_economy` の後に固定)。**前日終値の `controller()` から**首都連結集合を算出し、需要を確定する(「前日終値状態から需要を確定してから当日の移動・戦闘が起こる」)。
- **`FrontlineOrders`**: 前線計画・移動命令の再発行(冪等API 経由)。
- **`MilitaryAction`**(`handle_daily_military`): 募兵 → 日次補充 → 装備補充 → **経路検証 → 移動(侵攻・戦闘開始・即占領を含む)→ 日次戦闘 → 戦闘終了判定 → クリーンアップ → 組織率回復**。
- **`WarResolution`**: 戦争点数、降伏、講和。

### 2.5 補給連結性(`military/capital_connectivity.rs`、`daily_supply.rs`)
`connected_states_from_capital(capital: StateId, country, &StateRegistry) -> HashSet<StateId>`(首都から自国支配の陸上州を `neighbors` でたどる)。`daily_supply` が国家ごとに呼び(`country.current_capital_state_id()`)、`plan_country_daily_supply_with_frontline(country_id, stockpile, divisions, definitions, **connected_states: &HashSet<StateId>**, frontline_eligible)` へ渡す。`division.current_state ∈ connected` の師団だけが補給配分の対象。`is_frontline_supply_eligible`(P27-005)は、攻撃側の戦闘師団が**隣接する自国支配かつ連結の州**から1ホップだけ補給を受ける例外。補給の充足率は師団の `supply_ratio` を通じて**移動速度**(`supply_mod`)にも効く。

## 4. 型の境界(数値一致で変換しない)
- 新経路の位置は **`ProvinceId`**、所属は **`MapStateId`**、旧経路は **`StateId`(`usize`)**。**3つの間を数値の一致で変換しない**(P32-029 §3、M5 から一貫)。変換が必要なら、シナリオが書いた**明示の対応表**だけを使う(P32-031 の旧新比較 fixture と同じ作法)。
- 国家の識別: 旧経路は `CountryId(usize)`、新経路の経済シナリオは `label: u32`。戦争関係(`WarRegistry::are_countries_at_war`)は旧型の `CountryId`。**新経路の国家をどの型で表し、戦争関係をどこから得るかは §9 の判断事項**(推奨: 当面は `CountryId` をそのまま再利用し、新経路のシナリオが国家ラベルとの対応表を明示する)。
- 師団: 旧 `Division` を変更せず、**新経路用の型を並行して導入する**(D1 の方針。`Division` は §2.1 のとおり変更の波及が大きい)。新型は旧 `Division` と並存し、最終段階(M9)で名称を整理する。旧型から新型への自動変換は作らない。

## 5. 所有・実効支配・初期値・更新契機(責務の分離)
| 概念 | 粒度 | 責務 | 初期値(M6 の検証) | 更新契機 |
|---|---|---|---|---|
| **法的所有(owner)** | ステート(`MapStateId`)。元計画 D5 の推奨 | 領有。和平での移転・国家消滅・請求の単位(M7) | 検証用シナリオが `MapStateId` ごとに明示する。未所属のプロヴィンスは所有なし | M6 では更新しない(M7 の和平・移転) |
| **実効支配(controller)** | プロヴィンス(`ProvinceId`)。元計画 §7.1 | 誰がそこを実際に支配し、通行・補給・戦闘の判定に使うか | 既定は「その州の所有国」(旧経路の `controller()` が `controller_country` 未設定なら `owner` を返すのと同じ意味)。**検証シナリオが `ProvinceId` ごとに上書きできる**。ステート未所属のプロヴィンスは**既定なし**(明示しなければ誰の支配でもなく、通行不可) | 到着先に敵師団がいなければ即時(旧 `occupy_state` と同じ)、戦闘の攻撃側勝利、(M7)和平での所有移転に伴う正常化 |
| 占領進捗 | プロヴィンス | (§9 D8 の判断後)。**本番の旧経路には進捗が無い**(§2.3) | M6 の最初の実装では導入しない(旧本番と同じ即時占領を再現) | — |
| ステートの支配国 | 導出値 | 戦争点数・降伏・経済の帰属(D6) | **M6 では導出しない**(M7 の前に決める。M6 は P 単位の支配だけで足りる) | — |

**区別の維持**(重要): 次の3つは**別のデータ**で、互いから推定しない。
1. **経済シナリオの担当ステート**(`countries[].states`): 経済計算上の対応。所有・支配ではない。
2. **補給検証用シナリオの通行範囲**(`supply_connectivity_scenario.ron`): 検証入力。正式な国境・実効支配ではない。
3. **M6 の支配データ**(新設する検証用シナリオ): 検証入力であり、**正式な全世界の所有・実効支配データではない**(正式なデータは M9 の本番ワールド配置)。

**D9(P32-003 §15、P32-007 で承認済み)との関係**: 位置が重要な施設(港・要塞・鉄道駅など)と天然資源の所在地はプロヴィンス単位、人口・経済施設はステート単位。**占領時の施設利用・生産の扱い、施設の破壊・接収、補給の具体的な計算方法は「確定しない事項」のまま**(同 §15)。M6 の最初の単位は施設・資源・人口に触れず、占領は支配国の変更だけを扱う。

M6 以降の補給連結性では、通行可能集合を**支配データから導く名前つきの変換**(`passable_from_control(control, country) -> ExplicitPassable`)を用意するのが自然である(旧経路の `is_traversable = 陸 && controller == country` に相当。P32-029 §3 が予告した「支配モデルが将来出す境界は主体ごとの通行可能プロヴィンス集合」の実体)。補給検証用シナリオの通行範囲は、この変換の入力にしない。

## 7. 既存の `Reach` を日次補給へ渡す接続点、必要な入力
### 7.1 接続点
- 旧: `plan_country_daily_supply_with_frontline(..., connected_states: &HashSet<StateId>, frontline_eligible: &HashSet<DivisionId>)`。**位置の型が `StateId` に固定**されている。
- 新: `Reach::reached_ids()`(`ProvinceId` 昇順)/ `reachability(p)`。**型の違う `StateId` 集合へ変換してはならない**(§4)。
- 接続の方式(推奨は B。判断は M6-d、§9 U8):
  - A: 日次補給の計画関数を `ProvinceId` 版に複製する(旧と二重実装。需要・Hamilton 配分の規則が二重になる)。
  - **B: 計画関数の「位置が連結しているか」の判定だけを注入する形へ一般化する**(例: `is_connected: &dyn Fn(&Division) -> bool`)。需要・配分・備蓄消費は旧と共有し、旧は `StateId` 集合、新は `Reach` から判定を作って渡す。旧経路の既存テストが変わらず合格することを条件にする。
  - C: 旧 `Division` に `ProvinceId` を持たせる(§2.1 のとおり波及が大きく非推奨)。
- 前線補給の例外(`is_frontline_supply_eligible`)は、「隣接する自国支配かつ連結の州」を `ProvinceGraph` の隣接と支配データに置き換えれば成り立つ(M6-d)。

## 8. 新しい実行時状態と保存への影響

## 10. 最初の実装候補: M6-a「師団の初期位置と、隣接プロヴィンスへの移動」
**目的**: 検証地域(29 プロヴィンス)に師団を置き、**自国支配のプロヴィンスの間だけ**を移動できることを、旧経路と同じ規則(冪等な命令・費用 1 のダイクストラ・1ホップの日数式)で確認する。戦闘・占領・補給・戦争関係・AI・UI・保存は含まない。

### 10.1 必要な入力(検証用シナリオ。新ファイルで、正式な国境・所有・実効支配ではない)
- 国家: ラベル(U1: 旧 `CountryId` との対応表)。
- 支配: ステートごとの所有国(例: ステート20 → 国家A、22 → 国家A、21 → 国家B)、プロヴィンスごとの支配国の上書き(例: ステート未所属の 17903 を国家A の支配にする)。**未所属で明示しないプロヴィンスは誰の支配でもない**(U2)。
- 師団: `DivisionId`、所属国、初期位置(`ProvinceId`)、速度。
- パラメータ: 1ホップの基準日数(既定 5.0。U4)、補給係数の定数(既定 1.0。M6-d まで固定)。

### 10.2 命令の受理・拒否(`start_or_maintain_movement` の新経路版。旧の契約を保つ)
| 条件 | 結果 |
|---|---|
| 目的地が現在地、または既に同じ目的地へ移動中 | **受理(no-op)**。状態・経路・進捗を一切変更しない(旧の P27-004 契約) |
| 目的地までの経路が、所属国が支配するプロヴィンスだけで存在する | **受理**。`destination`/`path`/`target=None`/`progress=0`/`Moving` を**原子的**に更新 |
| 師団が存在しない | 拒否(`UnknownDivision`)。状態不変 |
| 目的地が未知の `ProvinceId`(水域・範囲外の陸のセルは ID が無い) | 拒否(`UnknownProvince`)。状態不変 |
| 目的地が自国支配でない(他国支配・誰の支配でもない) | 拒否(`DestinationNotPassable`。戦争関係が入る M6-b までは敵支配も拒否) |
| 経路が無い(自国支配のプロヴィンスの連結部分の外・分断) | 拒否(`NoPath`)。**既存の状態を変更しない**(旧と同じ) |
| 師団が移動できない状態(M6-a では `Idle`・`Moving` 以外は存在しない) | (M6-b で `Fighting`/`Retreating` を追加) |

経路: 辺の費用 1、同費用の tie-break は `(費用, ProvinceId 昇順)`(旧の `(cost, StateId)` と同じ規則)。隣接は `ProvinceGraph`(六角形の辺の接触。河川は妨げない)。

### 10.3 状態が更新される時点
- **命令の時点**: 受理されたときだけ、`destination`/`path`/`target`/`progress`/`status` を原子的に更新。位置(`current_province`)は**変えない**。
- **日次の移動処理の時点**: `DivisionId` 昇順に処理。`target` が空なら `path` の先頭を取り、空なら到着(`Idle`)。1ホップの日数 = `max(1, 基準日数 × 費用 / (速度 × max(補給係数, 0.5)))`。進捗が 1.0 に達した日に `current_province` を更新。到着先が(命令後に支配が変わるなどで)通過不可になっていれば**停止**(旧の `validate_and_stop_invalid_movements` と同じ)。
- 位置と命令は**実行時状態**で、保存しない(§8)。

### 10.4 CLI またはテストで確認できる結果(具体例。検証地域の実ファイルから確認した隣接)
- 18309(ステート20)の隣接: 18109・18308・18310・18499・18500(すべてステート20)。18308 の隣接は 18309・18499。
- 例1: 国家A の師団が 18309 → **18308**(隣接、同じステート内)。基準日数 5.0・速度 1.0 なら 1ホップ 5 日。5日後に 18308 に到着して `Idle`。同じ命令の再発行は no-op。
- 例2: 18309 → **17266**(ステート22)。経路は `18309 → 18109 → 17903 → 17693 → 17484 → 17266`(全域で最短、5ホップ)。**17903 はステート未所属**なので、国家A の支配として明示した場合だけ受理され、明示しなければ拒否される(`NoPath`: 範囲内の他の経路が無い)。これは M5 の「未所属は明示すれば橋渡しになる」と同じ構造で、**ステートをまたぐ移動がプロヴィンス単位で成立する**ことの確認になる。
- 例3: 18309 → ステート21 のプロヴィンス(国家B の支配)は `DestinationNotPassable` で拒否。
- 例4(旧経路との一致): 旧 `process_movement` と同じ連なりの旧 `StateRegistry`(1州=1プロヴィンスの fixture、新旧IDの対応表を明示)を作り、同じ命令・同じ日数で、**旧の到着日と新の到着日が一致する**ことを比べる(M5-b の旧新比較と同じ作法)。意図した差は、旧は手書きの有向隣接、新は六角形から導く無向隣接。
- 例5(決定性): 師団の登録順・命令の発行順を入れ替えても結果が同一。同費用の複数経路がある場合の tie-break が固定。
- CLI: `world_move_check --scenario <師団・支配の検証用ファイル> --days N`(仮称)。各日の師団ごとの位置・状態・進捗を昇順で表示。終了コードは既存の CLI と同じ区別(0 = 正常な判定、64 = 引数の誤り、65 = 入力不正、66 = 読込失敗)。正常な拒否(命令の拒否)と入力不正を区別する。

### 10.5 範囲外と完了条件
- 範囲外: 戦闘・占領・戦争関係・補給(`supply_ratio` は定数)・AI・前線・UI(`map/division_*` の描画。GUI は M6-f でユーザー確認)・保存・経済への接続。
- 完了条件(案): 新規の純粋な関数とテスト、CLI の実出力、旧経路との到着日の一致、全体テストと clippy が合格し、旧経路・経済・保存・静的識別・`ECONOMY_RULES_REVISION` が不変。経路探索の**性能**は、検証地域(29)と測定専用の 35,221 ノードの両方で1回の命令の費用を測る(P32-031 の1主体の到達判定は約 0.4〜1.9 ms で、同程度と見込まれるが未測定。M6-a で測る)。
