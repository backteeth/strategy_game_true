## 4. 補給源・到達判定・前線補給
### 4.1 検証用 RON(`supply`。省略可)
```
supply: ( countries: [ (country: 1, capital: 18309, military_supplies: 100.0), ... ],
          divisions: [ (division: 1, supply_usage: 1.0), ... ] )
```
- 設定がないシナリオ(M6-a〜c)は従来どおり(補給なし。充足率は常に 1.0。テストと CLI の出力の一致で確認)。設定がある場合の検証(code): `supply-duplicate-country`・`unresolved-country`・`supply-unknown-capital`・`supply-capital-not-controlled`(首都は初期に自国の支配下)・`supply-invalid-stockpile`・`supply-unknown-division`・`supply-duplicate-usage`・`supply-invalid-usage`・`supply-missing-usage`(設定のある国家の師団には補給消費量が必要)・`supply-usage-without-country`。直接構築でも重複・不正な備蓄・不正な補給消費量は拒否。
### 4.2 到達判定
- その国の**実効支配下にある陸上プロヴィンス**を `ProvinceControl` から導き、首都を起点に**既存の `reach`**(P32-030)で判定する。**首都が自国の支配を失ったら到達集合は空**(旧と同じ)。
- **`Reach` の「不明」(範囲外の陸を通る経路があり得る)は確認済みの到達に含めず**、件数を別に出す(CLI・報告の `connected` と `unknown`。テスト: 範囲外の陸をはさんだ先は不明で、その師団の充足率は 0.0)。実データの検証地域では、国家1の到達は首都のあるステート側の 14 件で、孤立したプロヴィンスは不明 3 件。
### 4.3 前線補給の例外(旧 `is_frontline_supply_eligible` が基準)
次をすべて満たす師団だけ: ①現在地が首都と連結した集合にない ②現在地の支配国が自国でない ③進行中の戦闘に**攻撃側として**参加している ④隣接する**自国支配のプロヴィンスが首都と連結している**。例外の対象の現在地は連結集合に入れない(連鎖投射なし)。**同じ師団の需要は一度だけ計上**(テスト: 需要 = 人員比に比例する値で、連結扱いの需要と一致)。対象外のテスト: 防御側、戦闘に参加していない師団、隣接する連結した自国支配地がない場合。

## 6. 補給率の移動・戦闘への反映
- **旧の更新元・参照点**(実コードで確認): 日次補給の充足率 `division_supply_fulfillment` は、`Economy` Set の `process_daily_military_supply_consumption` が毎日確定し(前日終値の状態)、**戦闘計算**(`combat_calc` の `supply_fulfillment_of`)が同日の `MilitaryAction` で参照する。移動の `Division.supply_ratio` は別の値で、初期値 1.0(`loader`・`recruitment`)、更新するのは `process_supply`(州の物流容量から)だが**本番から呼ばれない**。移動は `max(supply_ratio, 0.5)` を参照する(→ 本番では常に 1.0)。
- **新経路**: その日の最初に確定した配分結果が、**その日の移動と戦闘**に使われる(以後の日は、次の補給の計画まで同じ値)。移動の補給係数は旧と同じ下限 0.5 を維持: 1ホップの日数 = `max(1, 5 / (速度 × max(充足率, 0.5)))`。
- テスト(実測): 充足率 1.0 → 5日、0.8 → 7日(5/0.8 = 6.25日/ホップ)、0.5 → 10日、**0.3 → 10日・0.0 → 10日(下限 0.5)**。日次補給を通した場合も、備蓄 1.0 を2師団で分けると各 0.5 で 10日(補給なしの設定は 5日のまま)。戦闘: 攻撃側が補給 0.5・守備側が 1.0 の日の戦闘の損害が、旧の `resolve_combat_day_multi_with_supply` に同じ充足率を渡した結果と一致し、充足率 1.0 の場合の結果とは異なる(その日の配分が戦闘計算に使われる)。

## 7. 再計算(国家ごとの `Reach` のキャッシュ)
- **キャッシュするのは国家ごとの `Reach`**(と、そこから導いた確認済みの到達集合)だけ。到達集合を再利用する日にも、**需要・前線補給の資格・備蓄配分はその日の師団位置と戦闘状態で計算し直す**(テスト: 再利用した日も備蓄が毎日消費される)。
- **無効化**: `ControlChanged` と `countries_to_invalidate`(占領で支配が変わったプロヴィンスの変更前・変更後の支配国。重複なし)、検証用の `set_controller`(CLI の `--control`。変更前・後の支配国)、`set_capital`(CLI の `--capital`。その国家)。**グラフが差し替えられたとき**(`GraphSignature` の不一致)は全国家のキャッシュを捨てる。無効化された国家は**次に補給を計画する時点で**計算し直す(当日の占領による再計算も同じ)。
- テスト: 占領で無効化されるのは前の支配国と新しい支配国だけで、無関係な国家は再利用(`reach_recomputed` が偽)/ `set_controller` は変更前後の2か国だけ / `set_capital` はその国だけ / グラフの差し替えで全国家が再計算 / CLI でも古い結果が残らない(`cli_02`・`cli_03`・`cli_07`)。

### 日次の時間予算の案(提案。決定ではない)
- 既定は**到達結果を再利用**(100国・1,000師団で補給の費用 約 0.7 ms)。占領・首都変更で**変わった国家だけ**を翌日に再計算する(占領の多い日でも国家数の約1割なら 5〜8 ms)。
