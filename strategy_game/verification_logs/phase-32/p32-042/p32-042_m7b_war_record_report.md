## 1. 実装(`src/world/war_record.rs`、純粋な Rust・Bevy 非依存)

- **記録** `WarRecord`: `MapWarId`(旧 `common::WarId` とは別の型。数値で対応付けない)、両陣営 `WarSide`(代表国 1 + 支持国)、対象 `MapStateId` 1 件、開始日、終結 `WarEnd { 日, 結果(白紙講和 / 攻撃側勝利 / 防御側勝利), 理由 }`。日は呼び出し側の日番号。
- **交戦関係は稼働中の戦争から導出**: `Conflicts::sync` が `MapMilitary` の交戦関係を、「稼働中の戦争の両陣営の全組み合わせ」+「記録を持たない従来の組(シナリオの `wars`)」の和集合で置き換える。移動・戦闘は従来どおり `MapMilitary::at_war` を見る。
  `wars` だけのシナリオ(`division_battle_scenario.ron`・`division_territory_scenario.ron`)は記録なしで従来どおり動く(テストで `sync` が何も変えないことを確認)。同じ組を記録と `wars` の両方に書くことはシナリオの入力不正。
- **シナリオ**: `war_records: [(id, attacker, attacker_supporters, defender, defender_supporters, target_state, start_day)]`(省略可。国家ラベル)。未知のステート・ラベル、重複・同じ代表国・両陣営に同じ国は全件報告する入力不正。
- **終結 API** `plan_end_war`(状態を変えない)→ `apply_end_war`(**適用の直前に複製へ実行して再検証**し、結果が計画と一致したときだけ適用)。`end_war` は両方をまとめて行う。日次処理(`advance_day`)の間に呼ぶ。
  条件 `PeaceTerms::White` / `Cession { cancel_battles }`(防御側の代表国 → 攻撃側の代表国。攻撃側の勝利)。割譲は M7-a の `territory::execute`(検証・適用の本体)を再利用し、戦争の終結・領土移転・関連戦争の整理を 1 回の適用で行う。検証はすべて変更の前(失敗しても何も変えない)。
- **拒否** `EndWarError`: 未知の戦争、**終結済み**(`AlreadyEnded` が終結の日・結果を持つ)、開始日より前、交戦関係が記録と不一致(記録を経由しない変更)、割譲の拒否(M7-a の `TransferError`)。適用の拒否 `EndWarApplyError`: `AlreadyEnded` / `Stale(Invalid | OutcomeChanged)`。

## 2. 採用した規則(終結の順序は `war_record.rs` の冒頭にも記載)

| 項目 | 規則 |
|---|---|
| 連鎖(決定の順) | ①要求の戦争を終結(白紙講和 → 結果 WhitePeace / 理由 WhitePeace、割譲 → AttackerVictory / Cession)。②割譲で消滅する国(防御側の代表国が目標だけを所有)が代表国の**別の稼働中の戦争**(ID 昇順)は**対陣営の勝利**(理由 AttackerEliminated / DefenderEliminated)、**支持国としてのみ**参加なら陣営から除く(戦争は継続)。③割譲したステートを目標とする**残りの**稼働中の戦争(ID 昇順)は**白紙講和で失効**(理由 TargetOwnerChanged)。**同じ戦争に②と③が当てはまる場合は②(消滅による決着)を優先**(②を先に処理し、③は残りだけ) |
| 敵対が解けた組 | 連鎖の前後で導出した組の差。**別の戦争(従来の組を含む)で敵対が続く組は維持**する(結果に `hostility_kept`) |
| 戦闘 | 敵対が解けた組どうしの進行中の戦闘を、勝敗・占領・損失なしで中止し、参加師団を待機にする(割譲では M7-a の戦闘中止に合流)。維持される組の戦闘は触らない。割譲ステート内の維持される組の戦闘は、M7-a と同じく**番号の明示**が必要(なければ拒否) |
| 占領の正常化 | プロヴィンスの実効支配国と法的所有国(移転後)が、敵対が解けた組なら法的所有国の支配へ戻す(旧 `normalize_occupations_of_ended_war` の新経路版) |
| 師団の帰還 | 移転・正常化後の位置が**自国支配でも交戦相手の支配でもない**(支配国あり)師団のうち、位置の支配国・位置の旧支配国・法的所有国のいずれかと敵対が解けたもの。帰還先は M7-a と同じ(隣接する自国支配 → 自国支配の最小 `ProvinceId`、戦闘なしの地点。なければ解散 `NoReturnProvince`。撃破とは別)。帰還した師団の経路・目的地・進捗は破棄。**それ以外の移動命令は触らず**、次の `advance_day` の経路検証に任せる |
| 休戦 | **明示した講和(白紙・割譲)だけ**、代表国間(攻撃側の代表国と防御側の代表国)に **1825 日**。終了日 = 終結日 + 1825、**前日まで休戦・終了日から切れる**(旧 `is_at_least` と同じ境界)。支持国との間には作らない。消滅した国との休戦は消す |
| 補給キャッシュ | 無効化: 実効支配が変わったプロヴィンスの前後の国(正常化分)、敵対が解けた組の国、割譲の移転が無効化した国(第三国を含む)。次の補給計画で新しい首都・支配から再計算(テストで `reach_is_cached` と `reach_recomputed` を確認) |

## 3. 旧実装の確認(休戦・派生して終わる戦争)— **新旧の差あり。ユーザー判断が必要**

旧 `war/peace.rs::execute_peace_settlement` の読解(2026-11-26。実行時のトレースではなく、コードと `country/elimination.rs` の確認):
- 終結のたびに(⑨)`diplomacy_registry.set_truce(attacker, defender, 今日 + 1825 日)` を**その戦争の代表国間**に設定する。**派生して終わる戦争も同じ関数を通るので、休戦を作る**: ①同じ目標の別戦争の失効(`invalidate_other_wars_targeting_state` が `execute_peace_settlement` を白紙講和で呼ぶ)、②消滅による決着(`end_other_primary_war_due_to_elimination` が `AttackerEliminated` / `DefenderEliminated` で呼ぶ)。
- 国家消滅(`apply_country_elimination`)は、他戦争の終結のあと、**消滅国が絡む関係の休戦を消す**(外交清掃)。ただし割譲の戦争自身は消滅処理の**後**に `execute_peace_settlement` で終結し、休戦を設定するので、旧では消滅国との休戦が残り得る。

**新経路の扱い(今回の指示どおり)**: 休戦は**明示した講和だけ**に作る。派生して終わる戦争(同一目標の失効・消滅による決着)は休戦を作らない(旧は作る)。消滅した国との休戦は消す(旧の割譲戦争自身は残り得るが、消滅国との間に意味がないので消す)。
→ 派生して終わる戦争にも休戦を作る(旧と同じ)にするかは**未決**。作る場合は `execute` の終結の記録の箇所で、`ended` の各戦争の代表国間に同じ日数を設定する小さな変更で済む(テスト `cession_expires_…` の「失効した戦争2 の代表国 3-1 に休戦を作らない」の期待値を変える)。

## 8. 追記(P32-043 / M7-c): 休戦の既存ルールを維持した理由
M7-c(戦争点数・降伏)は**判定結果を返すだけ**で、講和を適用しない。そのため休戦の規則は変えず、次のとおり維持した。
- 休戦は**明示した講和(終結 API の白紙講和・割譲)だけ**が、代表国間に 1825 日で作る(§2。旧 `execute_peace_settlement` と同じ日数・同じ境界)。
- 降伏の判定は講和ではない。降伏を講和として適用するのは M7-d で、そのとき終結 API を通るので、休戦は既存の規則どおり(代表国間 1825 日)に付く。M7-c で休戦の経路を増やすと、M7-d の適用順序を先に決めてしまう。
- 派生して終わる戦争(目標の所有国が変わった失効・国家消滅による決着)に休戦を付けるかは、§3 のとおり**未決のまま**(旧は付ける、新は付けない)。降伏の適用(M7-d)で同じ問題が再び出るので、M7-d の着手時にユーザー判断を求める。
