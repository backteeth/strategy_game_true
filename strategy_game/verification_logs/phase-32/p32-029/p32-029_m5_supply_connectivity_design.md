### 1.2 補給連結性が M5 のものであることの確認と、元計画に対する推奨着手順
補給連結性は元計画のとおり **M5** に属し、別の段階ではない。ただし、元計画の文言どおり「旧 `capital_connectivity` を新マップへ載せ替える」には、**旧モデルが前提にしていて、新マップにまだ無いもの**がある(§2.2):

1. 旧モデルの通行条件は「`!is_sea && controller() == country`」で、**支配国(controller)**に依存する。新マップには支配(占領)モデルが無い(D6 は M7 前に決定する後続事項)。
2. 旧モデルの補給起点は `capital_state_id` で、国家に首都がある。新経済シナリオの `ScenarioCountry` に首都は無い(`states` は経済上の対応のみ)。
3. 旧モデルの消費側(師団の `current_state`、日次の需要・配分)に対応する、新マップ上の軍(師団の位置)は M6。

推奨する着手順(元計画の M5 を、次の3段に分ける。**元計画の完了条件は変えない**):
- **M5-a 純粋な到達判定**(支配・軍・経済に接続しない。通行条件は**明示入力**): 地理的な経路の存在だけを、P グラフで判定する。
- **M5-b ステート単位への集約と、D10 の性能データ**: 結果を `MapStateId` 単位へ集約し、約 35k ノード・複数国家の規模で BFS の時間を測る(元計画の「完了条件」にあたる)。
- **M5-c 検証シナリオからの接続**: 明示入力を検証用シナリオのファイルから与え、CLI で確認できるようにする(新しい経済・保存への影響の有無をここで精査)。
軍・補給量・日次配分への接続は、**M6 以降**(師団の位置が P になってから)。M5 の範囲で「補給量や軍への効果」までは完成させない。

### 2.3 旧モデルから学ぶべき既知の事故(設計への反映)
P26-006 は、連結性を導入すると「戦闘力が地理(支配)に依存する」という新しいフィードバック経路ができ、保存対象外の AI 再評価フラグ(`CountryAiState.dirty`)との組み合わせで、保存・再開の一致が稀に崩れる既存の非決定性を顕在化させた(同報告 §40。当時は新設計に持ち越した既知 finding)。**新マップで連結性を経済・AI の判断へ接続するときは、判定結果が状態の一部ではなく純粋な導出であること、再開後の一致、評価タイミングの保存の扱いを、最初の接続の段階で検証項目にする**(§7)。

## 3. 連結性の責務の分離

「つながっている」を次の4層に分ける。**層は互いに独立した入力と出力を持ち、下位の層を実装しただけで上位の層が完成したことにはならない。**

| 層 | 問い | 入力 | 出力 | 初回(M5-a/b)の扱い | 誰の責務 |
|---|---|---|---|---|---|
| **L1 地理的な経路の存在** | プロヴィンス A から B へ、**陸のプロヴィンス**を隣接で辿って行けるか | 静的: 地図・プロヴィンス表(`WorldModel`)・隣接 | 隣接グラフ、辺の事実(河川の有無・ステート境界か) | **実装する** | 世界層(`world`) |
| **L2 通行できる主体の条件** | 対象(国家・部隊)がそのプロヴィンスを通れるか(所有・支配・通行権・戦況) | **動的/シナリオ入力**: 主体ごとの「通れるプロヴィンスの集合」(明示) | 通行可否の述語 | **明示入力として受ける**(支配モデルは実装しない) | 将来の支配モデル(M6/M7)。初回はシナリオ |
| **L3 輸送能力** | 経路上にどれだけ運べるか(道路・鉄道・港の容量) | 能力の定義(未決) | 経路・辺ごとの容量 | **扱わない**(§4.5) | 未決(ユーザー判断) |
| **L4 実際に届く補給量** | 需要に対し、実際にどれだけ届くか(配分・備蓄・距離・遅延) | 需要(日次需要)、備蓄、L1〜L3 | 師団・国家ごとの充足率 | **扱わない**(M6 以降) | 旧 `daily_supply` の新マップ版 |

- **M5-a/b は L1 と、L2 の「受け口」だけ**。出力は「到達した/しなかった」の集合と、理由つきの判定(§4.3)。**補給量・軍への効果は完成しない**(L3・L4)。完了報告で、到達判定を補給の完成と書いてはならない。
- 既存の物流(`compute_logistics`)は、**ステート内部の経済の数値**であり、L3 の候補入力にはなりうるが、そのまま L3 にしない。P26-001 が `logistics_capacity` を軍事補給の容量に流用しない(モデル3の却下)としている判断を、新マップでも尊重し、再検討する場合はユーザー判断とする。
- 経路判定の**区画の単位は ProvinceId**(元設計 §3: 補給連結性は「P グラフ上の BFS(または S レベルで計算して P へ展開)」。D10 は M5 で実測して決める)。**経済側への集計単位は MapStateId**(人口・施設・生産・物流は M4 で S 単位)。両者の橋は、`WorldModel::state_of` / `provinces_of`(所属の正本)だけ。**`ProvinceId`・`MapStateId`・旧 `StateId` を数値の一致で変換することはしない**。
- **ステートをまたぐ経路・分断の表現**: 到達集合は ProvinceId の集合として持ち、ステート単位の要約(`StateReach`)を別に導出する。ステート内の一部だけ到達(例: 内部に通れないプロヴィンスがあり、ステートが分断される)を `Partial` として表せる。ステート単位だけで判定すると、この分断が見えない(D10 の P 単位を推奨する理由)。
- **国家との対応**: `ScenarioCountry.states` は「経済計算上の対応」で、所有・占領・通行権の正本ではない。**通行条件として黙って流用しない**。使う場合は、検証用シナリオが「この国家の通行可能プロヴィンス」を**明示する**。明示のしかたの一つとして、シナリオ側で `passable_states: [..]`(ステート単位の記述)を許し、読み込み時に `provinces_of` で展開する、**名前つきの変換**(`ExplicitPassable`)を用意する。これは検証用の便宜で、支配の導出ではない(名前とドキュメントで明示)。
- **正式な支配モデルが未実装のとき**: 入力の受け口(§4.2)だけを定義し、支配モデルが将来出す境界は「主体ごとの通行可能プロヴィンス集合」(`Passability`)とする。M6/M7 はこの境界へ、支配(P 単位。D6)から導いた述語を渡す。

## 4. 推奨する最小構成(M5-a / M5-b / M5-c)

### 4.1 配置と純粋性
- `src/world/` に、**Bevy 非依存・保存非依存・経済非依存**の導出モジュール `world::connectivity`(仮称)を置く。入力は `&WorldModel`・`&HexMap`(既存の `derive_world_geo` と同じ形)。`MapEconomySimulation` へ触れず、**コピーも作らない**。結果は純粋な値(`ProvinceGraph`、`Reach`)。UI・CLI・将来の補給計算は、同じ関数を呼ぶ。
- `ProvinceGraph`(静的な導出): 全プロヴィンス(ID 昇順)の隣接リスト(各プロヴィンスの隣接 `ProvinceId` を昇順)。辺の属性は、**河川の有無**と**ステート境界か**(任意の付加情報。通行の可否には使わない)。**水域セルには節点が無い**。範囲外の陸セルへの隣接は節点にせず、節点ごとに「範囲外の陸と接する」フラグを持つ(§4.3 の完全性)。既存の `WorldGeoDerived` と同様に、地理の指紋と所属の署名を持ち、`is_current_for(model, map)` で古い結果を検出する。

### 4.2 入力(始点・終点・補給源・通行条件)
- **補給源(始点)**: `sources: &[ProvinceId]`(複数可。首都プロヴィンスや、後続の港・要塞を同じ口で扱える)。**シナリオが明示する**(初回は検証用ファイル。首都の概念は導入しない)。
- **通行条件**: `trait Passability { fn passable(&self, p: ProvinceId) -> bool }`。初回の実装は `ExplicitPassable(BTreeSet<ProvinceId>)`。**入力に載っていないプロヴィンスは通れない**(既定は拒否。既定値で補わない)。通れるかの判定は、主体(国家のラベル)ごとに1つ。
- **終点(問い合わせ)**: `ProvinceId`(または `MapStateId` の要約問い)。到達集合を1回の探索で求め、終点の問い合わせは集合の参照(複数の終点で再探索しない)。
- 通行条件に**河川は使わない**(初回)。海・湖・港・鉄道も使わない(§4.4)。

### 4.3 出力(到達可能・到達不能・対象外の区別)
```text
Reach {                       // 1主体・1回の探索の結果(純粋な値、保存しない)
    reached: BTreeSet<ProvinceId>,          // 補給源から通れる陸で辿れたもの(補給源自身を含む。通れる場合)
    complete: bool,                          // false = 探索の縁が「範囲外の陸」に触れた(その先は不明)
    sources_rejected: Vec<(ProvinceId, SourceProblem)>,   // 補給源が通れない / 存在しない / 水域・範囲外
}
enum Reachability {                          // 1つの終点についての判定
    Reachable,                               // reached に含まれる
    Unreachable,                             // 含まれず、かつ complete = true: 通れる陸だけでは確実に届かない
    UnreachableWithinKnownGraph,             // 含まれないが complete = false: 範囲外の先にある経路が不明
    NotApplicable(Reason),                   // 終点が節点でない: UnknownId / Water / OutOfScope / Unassigned(ステート未割当だが節点。通行は入力次第)
}
```
- **「到達不能」と「対象外」を混ぜない**。範囲外の陸・水域・未知の ID は「到達不能」ではなく「対象外」。完全でない結果での「到達不能」は確定させない(`AdjacencyLookup::NotRecorded{complete}` と同じ慣習)。
- 経路の取得: 必要なら `path(from, to)`(ID 昇順で隣接を展開する BFS の最短ホップ数の経路。**最短経路が一意でない場合、辞書順で最小の経路を返す**と規定)。初回は到達集合だけ必須、経路は任意(CLI の確認用)。
- ステート単位の要約(M5-b): `StateReach{ state: MapStateId, reached: usize, total: usize }`(`Full` / `Partial` / `None` を導出)。**ステートをまたぐ経路**は、`reached` の ProvinceId が複数ステートに属することで自然に表れる。

### 4.4 陸路・海路・港・鉄道の分け方
| 要素 | 初回(M5-a/b/c) | 後続 | 理由 |
|---|---|---|---|
| 陸路(プロヴィンス隣接) | **必須** | — | 旧モデルと同じ。唯一、地理の事実だけで定義できる |
| 河川 | 辺の事実を**記録**。通行は**妨げない**(推奨) | 渡河ルールを決める時 | 旧モデル・既存の規則に河川の通行規則が無い。決めると `Rivers` が Warn → Reject になり規則改訂が必要(§6) |
| 海路・港 | **扱わない** | 海域モデルと港の効果の決定後 | 水域にプロヴィンスが無く、海域の単位が無い。港の許可(海・湖)、効果、建設条件は未決。`water_adjacency` は事実のみ |
| 鉄道(駅・鉄道建物) | **扱わない** | L3(輸送能力)と一緒に | 位置施設の効果は未決。経済側の鉄道レベル(`railway_capacity_bonus`)は物流(経済)の数値で、経路の存在とは別 |
| 要塞・駅 | **補給源の候補として `sources` の口で受けられるだけ**。効果は確定しない | 効果の決定後 | 既存の定義があるだけで、新しい効果を確定しない |

### 4.5 L3・L4(輸送能力・補給量)へ進む前の選択肢(M5 の範囲外。ユーザー判断)
- A. **容量なし**: 連結 = 補給される(旧モデル2と同じ)。実装は M6 の日次配分の新マップ版で、容量は後続。
- B. 辺/プロヴィンスごとの容量とフロー(最大流・配分)。重く、仕様の決定が大きい。
- C. 補給源からの距離による減衰(旧モデル3。P26-001 で却下)。
推奨: **A のまま M6 へ進み、容量(B)は施設の効果が決まってから**。理由: 旧モデルの判断(却下の理由)が新マップでも変わっておらず、容量のデータ(鉄道・道路・港の軍事補給専用値)が無い。

### 4.6 経済 AI 等への接続点
- 現在、**経済 AI は連結性を参照しない**(旧経路の `country_ai`・`ai_core` にも新経路の `MapEconomySimulation` にも参照がない)。**M5 では経済 AI へ接続しない**(推奨)。
- 将来の接続点の候補(M6 以降): (1) 日次補給の新マップ版(`plan_country_daily_supply` 相当)が `Reach.reached`(ProvinceId 集合)と師団の位置(P)を受ける。(2) `MilitaryAiFacts` に、到達に関する**明示入力**(例: 補給から切断された師団の数。新しい戦略・脅威評価ではない)を足す場合は、`ItemKey::MilitaryInputs`(Reject)の対象で、規則改訂を伴う(§6)。(3) 戦争 AI の `offensive_delivery_division_ids` の新マップ版は M6。
- 接続の形: **`Reach` を受け取る側は関数の引数として受ける**(旧モデルと同じ。`connected_states` を引数で渡す)。グローバルな状態にしない。

## 5. 更新・再計算・保存・性能

### 5.1 静的グラフと動的な通行条件の分離
| 区分 | 内容 | 変化の契機 | 再計算 |
|---|---|---|---|
| 静的(導出) | `ProvinceGraph`(隣接・節点・辺の事実) | 地図・プロヴィンス表・所属の変更(指紋・署名が変わる) | `is_current_for` が偽になったときだけ。実行中は不変 |
| 動的/入力 | 補給源、通行可能集合(`Passability`) | M5 では検証用シナリオの静的な記述。**M6/M7 では支配の変化・首都の移転・戦況** | 入力が変わったとき |
| 導出(結果) | `Reach`(`reached`、`complete`)、`StateReach` | 上記のいずれかの変化 | 入力の署名が変わったとき |

- **毎日(毎フレーム)計算する必要があるか**: M5 では不要(入力が静的)。M6/M7 で支配が日々変わりうるとき、旧モデルは「毎日・国家ごとにゼロから再計算」(O(N+E))だった。新規模(約 35k 節点)でも、**まず毎日の再計算の費用を測り**(§5.4)、問題があれば「入力が変わったときだけ再計算」へ移す。**フレームごとの計算はしない**(日次処理の境界)。
- **キャッシュする場合の無効化条件**: 結果の鍵 = (グラフの署名, 通行条件の署名, 補給源の列)。**入力の署名が変わったらキャッシュを捨てる**。署名は、通行可能集合の ID 昇順列と補給源の列のハッシュ(決定的)。**部分更新(差分 BFS)は初回に入れない**。キャッシュは保存しない。
- **正本と参照**: 到達判定の**正本は純粋関数の戻り値**(`Reach`)。利用側(CLI・UI・将来の補給)は、同じ関数・同じ入力から得た値を参照する(結果をコピーして独自に更新しない)。`MapEconomySimulation` は `Reach` を持たず、`Reach` の元になる入力も、M5 の段階ではシミュレーションの外(シナリオファイル)に置く。
- **決定性・安定した出力順**: すべての集合・列は ID 昇順(`BTreeSet`/整列済み `Vec`)。隣接リストは `ProvinceId` 昇順、探索は FIFO(BFS)で、入力の列挙順(ファイル順・`HashMap` 反復順)に依存しない。終点の列挙・複数国家の出力も ID 昇順。旧 `connected_states_from_capital` の規約(隣接を昇順に整列、`HashSet` は集合の判定にのみ使う、`neighbors` が片方向でも逆を補わない)と同じ。**新マップの隣接は地理から導出するので常に対称**。

### 5.2 状態の区分(静的入力の追加か、動的状態の追加か、導出か)
| 追加するもの | 区分 | 保存・互換性判定への影響 |
|---|---|---|
| `ProvinceGraph` | **導出**(地図・所属から再生成できる) | **なし**。保存しない。静的識別の既存項目(`Grid`・`CellCoordinates`・`LandSet`・`ProvinceTable`・`StateMembership`)が地理の同一性を既に守っている |
| 補給源・通行可能集合(検証用シナリオ) | **静的入力の追加** | M5-a/b(`MapEconomySimulation` の外で、結果が経済に影響しない)の間は**なし**。**経済・AI の判断が読み始めた時**に、新しい静的識別の項目(仮称 `SupplyInputs`、Reject)が必要(§6) |
| `Reach` | **導出** | 保存しない(旧モデルの規約と同じ。再開後は現在の入力から再計算) |
| 支配状態(P 単位の controller)・占領進捗 | **動的状態の追加**(M6/M7) | **保存形式の変更が必要**(mapeco の新しい節 + `format_version` または節の版の引き上げ、または SaveGameV2 の一部)。M5 では追加しない |

### 5.3 保存への影響(今回は保存形式を変更しない)
- **M5-a/b/c の範囲(判定は経済に影響しない)**: mapeco の形式・静的識別・`ECONOMY_RULES_REVISION` に**変更は不要**。`MapEconomySimulation` の状態は変えず、「判定だけでは経済状態が変わらない」を自動検証で固定する。
- **変更が必要になる時点(明示)**: 次のいずれかが起きたとき、**同じ変更で**(1)判定表の `Warn → Reject`(`Rivers`: 河川が通行に使われる、`LocationFacilities`: 施設が計算に使われる)、(2)新しい静的識別項目の追加(補給入力。Reject)、(3)`ECONOMY_RULES_REVISION` の引き上げ、(4)動的な支配状態を保存するなら mapeco の節の追加と版の管理、を行う。**これは判定表の運用規則(`static_identity.rs` の注記)に従うもので、新しい方針ではない**。
- 既存の mapeco の保証範囲(保存・再開の一致、静的入力の項目別判定、拒否の理由)は M5-a/b/c で変わらない。**既存の保存は互換のまま**。
- SaveGameV2(M8)・旧 V1 の廃止(D11、未承認)を、M5 の前提にしない。支配状態の保存方法(mapeco の拡張か V2 か)は、M6 の設計で、M8・D11 との依存を確認して決める。

### 5.4 性能: 最初の実装の方針と、測定すべき規模・項目
- 方針: **BFS は素朴に実装する**(隣接リストは節点番号の連続配列、訪問済みはビット列/`Vec<bool>`)。過度な最適化(差分更新・並列化・SIMD)は入れない。D10 の判断に必要なデータを取ることが M5 の完了条件。
- 規模: (a) 実地図の陸セル 35,221(`generate_initial_province_table` で全世界の P 表を作る。**ステート配置は不要**で、P 表だけで節点・隣接は定義できる: P32-005 の `initial_numbering_is_deterministic…` テストと同じ作り方)。(b) 検証地域(29)。(c) P32-024 の合成ステート(1000 ステート ≈ 6,000 プロヴィンス)。
- 項目: ① `ProvinceGraph` の構築時間とメモリ(節点・辺の数: 陸 35,221 のとき辺 ≈ 3P)。② 1 補給源からの BFS の時間(全陸を通れる最悪ケース、通行可能が半分の中間ケース)。③ 国家数 3 / 30 / 100 の毎日の再計算の合計。④ ステート単位の要約の時間。⑤ 結果の決定性(順序を変えても同一)。**閾値で合否を決めない**(測定して D10 の判断材料にする。P32-024 の方式)。
- P32-028 で残った**識別情報生成(約 19〜20 ms)の重複**は、M5 の着手の条件ではなく、**保存・復元の後続の改善候補**として別に扱う(M5 の測定とは独立)。

## 7. 実装の段階と検証計画

### 段階 M5-a: 純粋な到達判定(推奨する最初の実装単位)
| 項目 | 内容 |

### 10.1 M5-a で具体化した判定(§4.3 の `Reachability` の条件)
§4.3 の4区分を、次の条件で実装した(`world::connectivity`)。
- **到達可能**: 通行可能なプロヴィンスだけを既知の辺でたどって着ける。起点自身は、通行可能なら到達集合に含まれる。
- **到達不能(確定)**: (a) 対象自身が明示条件で通行不可(理由: `NotPassable`)、または (b) 範囲外の陸をすべて通れると**仮定しても**経路が無い(理由: `NoRoute`)。
- **不明**: 通行可能で、既知の辺では着けないが、範囲外の陸をすべて通れると仮定すれば着ける(未知の領域を通る経路があり得る)。**「グラフが不完全だから全部不明」ではなく、この具体的な条件のときだけ不明**(設計書 §4.3 の `UnreachableWithinKnownGraph` を、より精密なこの定義に置き換えた)。
- **対象外**: ノードでないもの(未知の `ProvinceId`、水域・範囲外の陸・地図外のセル)。
- **入力不正**(判定ではなく `Err`): 起点が空、起点が存在しない、起点が通行不可(黙って通行可能にしない)、通行条件が存在しない ID を含む。
- 未割当の陸に `ProvinceId` を発行して「不明」を表すことはしない(範囲外の陸セルは、ノードにせず、セル単位の情報として保持する)。

### 10.2 §2.4 の記録値の補足(P32-030 で現在の実ファイルから再計算した結果)
§2.4 の「ステート 21 を通れないとすると、残る割り当て済みは 2 成分(6 と 7)」は、**ステート 20 と 22 だけを通行可能にした場合(ステート21と未割当 3 件は通行不可)**の値である。未割当 3 件を通行可能に含めると(「全ノード − ステート21」の16ノード)、未割当のプロヴィンスが橋渡しになって、**通行可能部分は 1 成分**になる(P32-030 で確認)。「ステート 21 を通行不可にした分断」は、未割当を通行条件に含めるかに依存する。
