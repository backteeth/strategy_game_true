## 4. 河川 direction の定義と根拠
ユーザーが制作ツールの仕様を確認した内容(本依頼で提示)に従う: 画面上が北、右辺を 0 として反時計回りに 0=東(q+1,r) / 1=北東(q+1,r-1) / 2=北西(q,r-1) / 3=西(q-1,r) / 4=南西(q-1,r+1) / 5=南東(q,r+1)。direction は河川が存在する辺であり、流下方向ではない。反対側は `(d+3)%6`。
実装: `data::RIVER_NEIGHBOR_OFFSETS` / `river_neighbor` / `opposite_direction`。
頂点との対応: セルの頂点 i は画像座標の角度 `60°·i − 30°`。仕様の検算式 `theta = −d·60°`、端点角 `theta ∓ 30°` から、direction d の辺の両端は頂点 `(−d) mod 6` と `(1−d) mod 6`(`geometry::river_edge_corner_indices`)。テストで仕様の式と一致を確認。

## 5. 座標変換
河川の端点は、セル描画と同じ `HexGrid::corner_world`(画像→ワールドの Y 反転は `image_to_world` の1箇所)を通す(`geometry::river_edge_world`)。河川独自の変換は無い。拡大率・表示原点は従来どおり(1:1)。

## 6. 共有辺の正規化と描画
整数座標のみで正規化(浮動小数点の一致判定は不使用): 各レコード `(q,r,d)` と `(隣接座標, (d+3)%6)` を比べ、`(q,r)` が辞書順で小さい側を代表とし、`BTreeMap` で重複をまとめる(入力順に依存しない。入力 JSON は書き換えない)。

- 辺の両側のセルが揃わない境界辺は `neighbor_exists=false` として保持し、削除しない(修正版では0件)。参照元セルの欠落は読み込みエラー(別扱い)。
- 描画: 全辺を1つのメッシュ(縁取り+本体の2枚、帯状・両端を半幅延長して角で途切れない)。単一メッシュなので、チャンク境界を跨ぐ辺(修正版で 161 本)も欠落・二重なし。チャンクの塗りメッシュより上、選択枠・UI より下(z: 塗り0 < 境界線1 < 河川縁取り1.5 < 河川1.6 < 選択枠2/3)。
