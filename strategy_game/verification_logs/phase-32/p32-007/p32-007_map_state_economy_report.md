## 実装内容と共通化した計算経路
旧 `StateData` と新 `MapStateEconomy`(`MapStateId` キー)が**同じ中核計算**を通る。計算式の複製は無い。
- `economy::state_access::StateEconomyAccess`(新規トレイト): 計算が必要とするフィールドの読み書きの窓口(`StateData` と `MapStateEconomy` が実装)。`economy_key` は各集合の中での処理順・同率判定の数値で、旧 `StateId` と `MapStateId` の相互変換・同一視には使わない。
- 共通化した処理:
  1. **動員負担の按分**(最大剰余法): `population::mobilization::apportion_mobilized_manpower_by`(任意キー型)。旧 `apportion_mobilized_manpower` はこれへ委譲。
  2. **雇用計算**: `population::update::compute_employment`(純粋関数)。旧 `update_state_population_and_employment` はこれへ委譲。
  3. **物流計算**: `logistics::update::compute_logistics`(純粋関数)。旧 `update_state_logistics` はこれへ委譲。
  4. **月次の人口・雇用・物流更新**: `economy::state_access::update_monthly_workforce_and_logistics`(按分→雇用→物流)。旧 `economy::handle_monthly_economy` もこの関数へ切り替え。
  5. **生産(施設規模を使う既存の経済計算)**: `economy::production::process_country_production(_with_outcome)` を `StateEconomyAccess` でジェネリック化。式・処理順・丸めは無変更で、旧経路の呼び出し(`&mut [&mut StateData]`)は型推論で従来どおり。
- 新規: `economy::map_state`(`MapStateEconomy`、`MapStateEconomyRegistry`(`MapStateId` 昇順・同一ステート 1 件)、検証用シナリオ `EconomyScenario`、データ検証)。静的な世界定義(`world::MapStateDef`)と時間経過する経済状態を別データとして保持し、所属ファイル・境界を経済データの保存先に流用していない。**実行時のみで、セーブ形式へは永続化しない**。
