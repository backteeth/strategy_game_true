## 3. 旧手動建設仕様の調査結果(UI `ui/state_panel.rs` から処理本体まで追跡)
- 受付(`handle_build_buttons`): プレイヤー国が有効 → 州が選択されている → **州の所有国がプレイヤー** → 建物定義がある → CrystalMineは発見済みMagicCrystal鉱床が必要 → 通常Mineはクリスタル専用州で不可 → 現在レベル < 最大 → 同じ州・同じ施設がキューに無い → 国庫 ≥ 費用。この検証は**画面側のSystemの中だけ**にあった(処理本体は無かった)ため、判定部分を共通関数へ切り出した。
- 支払い: 受理時に`treasury -= construction_cost`を1回。物資の消費は無い。キューへ`ConstructionQueueItem`(目標レベル=現在+1、必要進捗=定義、支払済み費用=費用、状態InQueue)。**プレイヤーの注文数の上限は無い**(AIだけ最大2件)。
- 識別: 注文の識別子は無い(キューの位置と「州+施設」の組だけ)。
- キャンセル(`handle_cancel_queue_buttons`、Cキー): 消滅済み国家は不可。**キューの最後の1件だけ**を取り出し、`paid_cost × REFUND_RATIO(0.5)`を国庫へ加算。待機中・建設中の区別、進捗、端数処理(丸めなし。表示だけ整数)に依存しない。
- 完成後: 日次の建設処理が完成した注文をキューから外し、施設レベル+1。完成後の注文はキューに無いのでキャンセルできない。
- 既存仕様に無いもの(推測で足していない): 識別子による個別キャンセル、完成保留(資源設定の変更)の扱い、注文主体のラベル、資源設定の前提。

## 4. 注文主体と対象の確認方法
要求は 注文主体(シナリオの国家ラベル)・対象`MapStateId`・施設。確認の順序: 国家が存在 → ステートが存在 → **そのステートが注文主体の経済計算上の対応関係に含まれる**(検証用シナリオの`countries[].states`。法的所有・占領モデルではない) → ステート単位の経済施設である(`BuildingType`の全種別が該当。位置施設は型が無く対象外) → 共通規則(上の順序) → Mineの資源設定(完成後の月次経済が入力不備で失敗する経路を受付時に塞ぐ。P32-009・010の仕組み)。旧`StateId`と`MapStateId`は数値で変換しない。
旧UIとの差(新しく見つかった差の解消): 旧UIにある「CrystalMineは発見済みクリスタル鉱床が必要」は、P32-010の新経路の受付に抜けていたため、共通規則へ含めて揃えた。

## 5. 注文の識別と状態遷移
- `ConstructionOrderId { country, seq }`: 発行した国家ラベル+国家ごとの連番(再利用しない)。AIの注文にも発行される。配列位置ではなく、他の注文の完成・取消しで位置がずれても変わらない。**実行時のみ**(セーブ形式・永続化なし)。
- 遷移: 受理(支払い+キュー登録) → 待機中/建設中(日次で進捗+1) → 完成(施設+1、`OrderEnd::Completed`) または 取消し(`OrderEnd::Cancelled`、返金)。完成保留(Mineの前提が崩れた)は注文がキューに残る既存のP32-010の扱いで、同じ規則でキャンセルできる。
- 拒否理由: 完成済み(`AlreadyCompleted`)・取消し済み(`AlreadyCancelled`)・他国家の注文(`NotIssuersOrder`)・記録の無い識別子(`NoSuchOrder`)・空のキュー(`EmptyQueue`)・存在しない国家。拒否時は国庫・キュー・施設・記録を変更しない。

## 6. 費用・キャンセル・返金の規則と根拠
- 費用・必要進捗・目標レベル: 建物定義(`buildings.ron`)。AIと同じ`push_order`・同じ完成処理(`advance_construction_queue`)。所属プロヴィンス数で増幅しない(MapState#20の7件と#21の13件で同一をテスト)。
- 返金: 注文主体の国庫へ`paid_cost × 0.5`(旧UIの規則。`cancel_refund`)。端数処理・進捗・状態に依存しない。他国家の国庫へは入らない。
- **個別キャンセル(識別子指定)は旧UIに無い動作**で、新しい要件として追加した。返金の式は旧UIと同じで、新しい返金率・条件は加えていない。旧UIと同じ「最後の注文」(`Latest`)も用意し、旧UIと一致を確認した。
- 未決(新しいゲームルールは足していない): 進捗に応じた返金率、建設中のキャンセル可否の制限、完成保留時のペナルティ、プレイヤー注文数の上限(旧UIに無い)、消滅済み国家の扱い(検証用シナリオに国家の状態は無い)。

## 7. AIと手動注文の共存
同じ`ScenarioCountry`の国庫・建設キュー・進捗・完成処理を使う。手動注文は即時に国庫を減らすため、後続のAI評価は残りの国庫で判断する(テスト: 国庫1500に手動Factory 1000 → AIは残り500で動き、AIの注文の支払いは評価時点の国庫を超えない)。AIの費用・優先度・候補選択は変更していない(P32-010・012のテスト全件が引き続き合格)。履歴(P32-012)は手動注文・キャンセルでは更新・消去されない(月次生産の観測値だけ)。完成後の雇用・生産・財政は従来と同じ月次経路(テスト: Farm完成後の雇用 = 施設レベル×必要労働力の合計の手計算と一致)。
