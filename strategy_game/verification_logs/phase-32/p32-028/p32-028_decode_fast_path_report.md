## 3. 高速経路とフォールバックの構成

実コード: `map_economy_file::decode`(`decode_timed` の共通の本体)。

```
decode(text):
  fast = ron::from_str::<FileOwned>(text).ok()          // 本体の型つきの完全解析を先に1回。エラーは利用者へ返さず捨てる
  if fast = Some(file) && file.kind == "map_economy_state" && file.format_version == 2:
      return Ok(DecodedFile{identity, snapshot})        // 成功した解析結果をそのまま再利用(同じ本体を再解析しない)
  return decode_legacy(text)                            // 従来の経路: ヘッダー解析 → kind・版の判定 → 本体の解析(変更前と同じ処理)
```
- 高速経路が返すのは「型つきの完全解析に成功し、`kind` と版が現行のもの」だけ。**別の `kind`・別の版・解析の失敗・旧V1・欠落・重複・未知フィールド・後半の破損など、成功ではないものはすべて、従来経路が最初からやり直して従来の結果(判定・拒否理由・拒否順・位置情報つきのメッセージ)を返す。**
- `kind`・版の取得に、文字列検索・正規表現・フィールド位置の固定・先頭だけの解析は使っていない(型つきの解析の結果のフィールドを見るだけ)。高速経路は何も書き込まず、状態を変えない。保存・復元・確認の後続の検証・復元処理は従来と同じ1つの実装のまま。
- 利用箇所(すべて同じ `decode` を通る): 保存時の読み戻し検証、`load`、`inspect`、保存一覧、上書き前の既存ファイルの確認。

## 10. 保証範囲と残件
- 正常な保存の `decode`(保存の読み戻し、`load`、`inspect`、一覧、上書き前の確認)は、規模に対して線形で、1000 ステートでも数 ms〜10 ms になった。
- **残る遅い経路**: 別の `kind`・非対応の版・旧V1 のように型つきの解析が成功しない/`kind`・版が現行でない入力は、従来経路(`ron` の読み飛ばしを含む 2 乗の解析)で判定される。本体が正常で `kind` だけが違う巨大なファイルは、従来どおり数秒かかる(本タスクの対象外)。
