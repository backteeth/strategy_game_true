## 4. グラフと到達判定の仕様

### 4.1 グラフの構築と前提
- ノードは `ProvinceId`(ID昇順)。辺は、2つのプロヴィンスのセルが六角形の辺で接しているときに1本(無向。プロヴィンスの組ごとに1本で、接触箇所が複数あっても重複しない。自己辺なし)。隣接の計算は既存の `hexmap::data::hex_neighbors` を使い、別実装はない。**物理的な1辺は両側のセルから見えるので、小さい番号の側からだけ数える**。接触の数(`contacts`)と、河川のある接触の数(`river_contacts`。`river_edges()` の正規化済みの辺と、同じ向きの規約で照合)を辺の事実として保持する(通行の可否には使わない)。
- 水域(海・湖)・地図外はノードにならず、**水域を経由する辺は作らない**(辺は陸セル同士の直接の接触だけ)。
- 入力: `ProvinceGraph::build(&WorldModel, &HexMap)`(`validate_against_geography` の Authoring 検証に通ることを要求。通らなければ部分的なグラフを作らず `GraphError::InvalidWorld`)。プロヴィンス定義を直接渡す `from_definitions`(**複数セルのプロヴィンスを扱える**。現在の `WorldModel` は1陸セル=1プロヴィンス)。構造の検証: セルが地図にあり陸であること、セルを複数のプロヴィンスが持たないこと、複数セルのプロヴィンスの**セルが隣接でつながっていること**(つながっていない定義は `ProvinceNotContiguous` で拒否=区画内の瞬間移動を許さない。水域をはさんだセルも拒否)、ID・セルの重複がないこと。
- 範囲と完全性(`GraphScope`): `Coverage`、ノード数、ステート未割当のノード数、範囲外の陸セル数。`is_complete()` = 範囲外の陸セルが0。古い結果の検出用に、地理の指紋と、ノード(ID・セル・所属ステート)の署名を持つ(`is_current_for`)。
- `ProvinceId`・`MapStateId`・旧 `StateId` を数値で変換していない(ステートは `WorldModel::state_of` の所属ラベルとしてだけ保持)。アセット・保存済みIDは変更していない。

### 4.2 通行条件と起点
- 通行条件 `ExplicitPassable`: **グラフに存在しない ID を含む入力は、黙って捨てずにエラー**(`UnknownPassableProvinces`)。載っていないプロヴィンスは通れない(既定は拒否)。便宜の指定(`all_nodes`、`from_states`)も**呼び出し元の明示的な指定**で、`from_states` は名前つきの変換(所有・支配の導出ではない)。国家や範囲を列挙順から選ぶ経路はない。
- 起点: 順序・重複は結果に影響しない。**空、存在しない、通行不可の起点は `Err`(入力不正)**で、黙って通行可能にも到達不能にもしない(問題のある起点はすべて報告)。起点自身は、通行可能なら到達集合に含まれる。通行不可のプロヴィンスには進入しない。

### 4.3 4区分の判定条件
| 判定 | 条件 |
|---|---|
| 到達可能 `Reachable` | 通行可能なプロヴィンスだけを既知の辺でたどって着ける |
| 到達不能 `Unreachable` | (a) 対象自身が明示条件で通行不可(`NotPassable`)、または (b) **範囲外の陸をすべて通れると仮定しても**経路が無い(`NoRoute`)。いずれも確定 |
| 不明 `Unknown` | 通行可能で、既知の辺では着けないが、範囲外の陸をすべて通れると仮定すれば着ける(未知の領域を通る経路があり得る) |
| 対象外 `NotApplicable` | ノードでない(未知の `ProvinceId`、水域・範囲外の陸・地図外のセル) |

「不完全なグラフだから全部不明」にも、「未割当を無視して全部到達不能」にもならない。到達集合が範囲外の陸に接していないとき、または範囲外の陸を通れると仮定しても着けないときは、不完全なグラフでも**確定の到達不能**になる(テストで確認)。不明を表すためだけに未割当の陸をプロヴィンス化することはしない。

### 4.4 「未割当」の意味(混同しない)
| 用語 | 意味 | 扱い |
|---|---|---|
| **ステート未割当のプロヴィンス**(検証地域に3件: 17903 / 18110 / 18501) | `ProvinceId` は**ある**(プロヴィンス表に載っている)が、どの `MapState` にも所属していない | **ノードとして存在する**。通行できるかは、他のノードと同じく**通行条件の入力次第**(明示的に許可すれば通れる。許可しなければ橋渡しにならない) |
| **範囲外の陸セル**(検証地域の外の陸。35,192 セル) | 地図上は陸だが、`ProvinceId` が**ない**(プロヴィンス表に載っていない) | ノードにしない。**ID を発行せず、橋渡しにも使わない**。存在だけを保持し、「不明」の根拠にする |
| 通行条件で指定していない | `ProvinceId` はあるが、呼び出し元が通行可能に含めなかった | `Blocked`(対象としては `Unreachable(NotPassable)`)。「未割当」ではない |

`ProvinceId` がある対象を明示的に通行許可する(CLI の `--passable all`、`--passable-provinces`)ことと、`ProvinceId` のない陸セルを勝手に橋渡しにすることは別で、後者はしない。

## 10. M5-b/c へ渡す接続点と残件
- **M5-b**(ステート単位への集約と D10 の性能データ): `Reach`(到達集合)から `MapStateId` 単位の要約(`Full/Partial/None`)を導出する。`ProvinceGraph::build` に、全世界の P 表(35,221 ノード)での構築時間・メモリ、国家数 3/30/100 の毎日の探索時間の測定を加える(元の M5 の完了条件。**今回の小規模試験だけでは M5 の完了とは扱わない**)。旧小規模ケース(`connected_states_from_capital`)と同じ構造を新グラフで表したときの同結果の確認。接続点: `ProvinceGraph::{node_ids, neighbors, cross_state_edge_count, components}`、`Reach::reached_ids / unknown_ids`、`GraphSignature`。
- **M5-c**(検証シナリオからの明示入力): 補給源・通行可能集合をシナリオファイルから読み込み(既定値で補わない、存在しない ID・重複の拒否)、CLI で国家ごとに表示する。接続点: `ExplicitPassable::new / from_states`、`reach`。保存・経済には、この段階までは接続しない(接続するときは、判定表の `Warn → Reject`、新しい静的識別項目、`ECONOMY_RULES_REVISION` の引き上げを同じ変更で行う: 設計書 §5.3)。
- 残件(M5 以降): 輸送能力・補給量(L3・L4)、支配・所有・通行権(D6)、海路・港・鉄道・施設の効果、河川の渡河規則、経済・AI・軍への接続、支配状態の保存。
