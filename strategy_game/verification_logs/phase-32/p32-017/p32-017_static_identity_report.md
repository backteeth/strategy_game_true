## 2. 識別情報の整理(3種類)

1. 世界層の地理識別(FNV-1a): **世界ファイルに記録された値**。世界層の検証用で、ここでは使わない。
   (調査で判明: P32-015 の `context` はこの記録値を使っており、実際に読み込んだ地図からは作っていなかった。)
2. P32-015 の内部 `context`(FNV-1a 64bit): 計算結果を左右する静的入力だけの総合確認。直接 `restore` を呼ぶ経路の最後の砦。
3. 今回のダイジェスト(BLAKE3-256、21項目): ファイルに保存し、復元先の**実際に読み込んで使っている** `HexMap`・`WorldModel`・
   `BuildingRegistry`・シミュレーション・位置施設レジストリから毎回作り直して項目別に比較。ファイル内の値は採用しない。

「署名」は内容識別用ダイジェストで、**電子署名・改ざん者の認証・暗号学的な真正性の保証ではない**(ファイルを書ける者は自分で計算した値を書ける)。
SHA-256 のクレートは依存になく、BLAKE3 は既に Cargo.lock にある標準実装のため採用した(独自の暗号アルゴリズムは実装していない)。

正規化: 項目ごとに別の Hasher、先頭に方式名・版・項目名(長さ前置)。整数は固定長LE、文字列と列は長さ前置、`Option` は 0/1、浮動小数点はビット列そのまま(丸めない)。
非有限値は識別を作らずエラー(保存も拒否)。セルは `(r,q)` 昇順、IDはID昇順、資源・建物は `ALL` 順。HashMap列挙順・パス・更新日時に依存しない。

## 3. 判定表(依存関係の調査結果に基づく)

調査: `economy/`・`country/`・`building/`・`military/update.rs` に、地形・気候・植生・河川・位置施設・ステートの表示名/代表プロヴィンス・建物の `name` の参照はない
(戦闘の地形補正は引数 `_state` を無視する)。世界層も、属性・河川の変化は情報(Info)、陸集合の変化はエラー扱い。

| 項目 | 扱い | 利用する処理 / 根拠 |
|---|---|---|
| grid / cell_coordinates / land_set | 拒否 | 座標・プロヴィンス所在地・陸水の構造 |
| water_kinds(水域の海/湖) | 拒否 | 現在の経済は読まないが、海・湖の扱いが未決の規則のため保守的に拒否 |
| land_terrain / climate / vegetation | **警告** | 経済・AI・建設は読まない(参照なし+再開結果の一致テスト) |
| rivers | **警告** | 境界描画・地理集計(再生成可能な導出)のみ |
| province_table / state_membership / state_constraints | 拒否 | ID・所属・連結性(未決規則) |
| state_presentation(name_key・代表プロヴィンス) | **警告** | 表示のみ |
| scenario_structure / state_economy_static / resource_deposits / resource_setup / military_inputs | 拒否 | 日次処理・月次経済・生産・AI優先度2.5/2.9 |
| building_computation | 拒否 | 建設費・進捗・労働力・物流・維持費・産出・投入等 |
| building_presentation(`name`) | **警告** | 表示のみ |
| location_facilities | **警告** | 入力層のみで経済は読まない(効果は未実装)。提供の有無の差も警告 |
| economy_rules | 拒否 | 手で管理する改訂番号 |

警告は上の 7 項目のみ(テストで限定列挙を固定)。未知の項目名・欠落・重複・不正なダイジェスト・非対応の方式/版は拒否。
拒否項目が一つでもあれば全体を拒否し、併存する警告は許可されない。複数の拒否項目は全件報告する。
同じ変更が複数項目に現れる場合も、各項目を独立に判定する(例: 陸→水は land_set・water_kinds・land_terrain、すべて報告)。

## 4. 内部コンテキスト照合との関係

復元手順: 封筒検証 → 保存側識別情報の検証 → 復元先から識別情報を作る → 項目別判定(拒否があれば終了) → 候補の検証・再構築(P32-015 の `context` 照合を含む) → 成功時のみ置換。
`context` からは属性と河川を外した(警告で許す項目を内部照合が再び拒否しないため)。それ以外(grid・coordinates・land_set・所属・資源・国家・軍事・建物計算)は残っており、
無効化はしていない(テスト: 属性/河川の記録値が違っても直接 `restore` が通る / land_set・grid が違えば `ContextMismatch`)。
ファイルの `context` は採用せず比較のみ(P32-016 のテストが継続して通る)。人口・国庫・履歴・注文などの動的状態は、警告付きでも保存された値のまま復元(初期化・再計算なし)。

## 6. CLI

`--economy-save/--economy-resume/--economy-run`(従来どおり)。resume は「一致 N / 警告つき許可 M / 拒否 K」と、警告・拒否の項目・理由・影響を表示する。拒否時は非ゼロ終了で日次出力なし。
全不一致を無視するオプションはない。`--map-file`/`--buildings-file`/`--facilities-file` は入力ファイルの場所の選択のみ(判定は常にStrict+判定表)。
実出力: `cli_identity_output.txt`。同じ入力で 100日保存 → 別プロセス60日再開 = 連続実行の 101〜160日と **60/60行一致**(終了コード0、行数60、日付 04/12〜06/10 を確認)。
建物名の変更 → 警告つきで成功、建設費の変更 → 拒否(exit 1)。

## 8. 保証しない範囲・残件

- コード上の式・定数の変更は自動検出できない(`ECONOMY_RULES_REVISION` を手で上げる運用。対象は `p32-017_rules_revision_policy.md` に列挙)。
- 識別情報は内容識別であり真正性の保証ではない。位置施設は呼び出し側が渡した場合のみ内容を比較(渡さない場合は「提供の有無」の差として警告)。
- 鉱床の発見等が今後実行時に変わる場合、`discovered`/`development_level` は静的定義ではなく動的状態になり、責務の分け直しが必要(今回は実装しない)。
- ファイルのシンボリックリンク拒否のテストは、この環境では権限不足で**引き続き SKIPPED(未確認事項として引き継ぎ)**。権限・システム設定は変更していない。
- クラッシュ・電源断の永続性、ディレクトリ同期、TOCTOU は P32-016 と同じく保証しない。
- 世界読込の陸集合変化は読込時エラーになるため、CLI で「陸水変更の地図」を渡すと識別判定の前に世界の読込で止まる(判定そのものはライブラリのテストで確認)。
