## 3. 根本原因判定

原因は3つの独立した欠陥の合成である。

1. **損害式の不連続(1対1・複数師団の総量計算)**: 実効戦力は整数で、値域は0〜攻撃力(10〜15程度)しかない(実際の計算は`power*readiness_1000*org_ratio_1000/1_000_000`で、コメントの「×1000」スケールになっていない)。実効戦力が1未満へ切り捨てられると、`def_effective_with_terrain < 1`の分岐が分母を`1000`にする。分母が`1`から`1000`へ跳ぶため、損害が1000分の1に落ちる。
2. **`distribute_damage`のweight総和0(複数師団のみ)**: `total_effective <= 0`のとき全員に0を配分する。
3. **両陣営が0の場合の終了規則が存在しない**(今回は修正しない)。

## 10. 現行の戦闘System順序

## 11. outgoing damage式(現行)

`resolve_combat_day_with_supply`(1対1)と`resolve_combat_day_multi_with_supply`(陣営合計、1対1以外)。

```text
readiness_1000 = min(manpower比, equipment比, 補給充足率) を1000倍(整数、切り捨て)
org_ratio_1000 = organization/max_organization を1000倍(整数、切り捨て)
eff            = power × readiness_1000 × org_ratio_1000 / 1_000_000   (整数、切り捨て)
```

`power`は攻撃側なら`attack_power`、防御側なら`defense_power`。`eff`の値域は0〜power(約10〜15)であり、コメントの「固定小数点×1000」は実態と一致しない。地形補正`terrain_defense_bonus`は防御側`eff`へそのまま加算される(現在の地形は常に0)。

## 12. incoming damage配分式(現行)

1対1(攻撃側1・防御側1)は配分なし。損害総量がそのまま該当師団へ入る。

複数師団(`distribute_damage`):

```text
total_effective <= 0 のとき: 全員に損害0(組織率損害0)
それ以外: IDの昇順に share_i = total_loss × eff_i / total_effective(整数除算)、
          最後の師団が total_loss - Σ(既配分) を受け取る
```

## 13. manpower損害式

```text
defender_total_loss = attacker_eff × 100 / max(defender_eff + terrain, 1)      (defender_eff+terrain >= 1)
                    = attacker_eff × 100 / 1000                                 (defender_eff+terrain <  1)
attacker_total_loss = 同様に対称(攻撃側と防御側を入れ替え)
```

`DAMAGE_SCALE=100`。組織率損害 = manpower損害の1/10。適用は`apply_combat_casualty`(`saturating_sub`)。

## 14. Equipment損害式

`calculate_proportional_equipment_loss`が、実際に減少したmanpower(actual casualty)に比例して、損害適用直前の現在装備量を破壊する(P25-004)。manpower損害と同一のweightではなく、各師団の実際の人員損失に連動する。破壊された装備は国家備蓄へ戻らない。

## 15. damage丸め

整数除算(切り捨て)。複数師団では端数がIDの最大の師団へ集まる。

## 16. damage保存則

複数師団では`Σ配分 = total_loss`(最後の師団が残りを受け取るため)。ただし`total_effective<=0`のときは配分が0となり、損害が消滅する(保存則違反ではなく「配分不能」)。実際に適用される量は、対象の残存manpowerでclampされる(overkillは切り捨て)。

## 17. Division消滅条件

`resolve_participant_outcome`: `manpower==0`なら装備を全損させて削除。`organization>0`なら戦闘継続。`organization<=0`なら撤退を試み(撤退時に最大manpowerの10%を追加で失う)、撤退先がない・残manpower0なら削除。

## 18. 戦闘終了条件

`resolve_finished_battles`: どちらかの陣営の参加者が全員脱落したとき終了。防御側全滅→攻撃側勝利と`occupy_state`。攻撃側全滅→防御側勝利(支配権不変)。両者全滅→防御側勝利。**時間切れ・実効戦力0による終了規則は存在しない**。終了は損害による組織率0・manpower0だけで起きる。

## 19. controller変更条件

戦闘勝利時の`occupy_state`、または無防備な敵州への到着時の即時`occupy_state`のみ(P27-005で確認済み、今回変更しない)。

## 32. 採用候補

**P27-006は次の3点だけを変更する**(いずれも`src/military/combat_calc.rs`)。

- **修正M(損害総量の分母を連続にする)**: `<1`分岐の分母`1000`を`1`へ。すなわち`max(実効戦力+地形, 1)`だけを使う。実効戦力が1以上のケースは**完全に同一**で、0のときだけ`atk_eff × 100`(攻撃力10なら1000、manpowerの10%/日)になる。
- **修正T(切り捨て下限)**: 攻撃力・readiness・組織率がすべて正なのに`eff`が0へ切り捨てられる場合だけ、`eff=1`とする(真に0の場合は0のまま)。
- **修正C(候補1)**: `distribute_damage`で`total_effective<=0`のとき、現在manpower比で配分する。同じIDの昇順・最後の師団に端数を集める既存規則を使う。

修正M+T+C をまとめて一時適用して測定した(§33〜§40)。

## 33. 正規配分式

```text
weight_i        = eff_i                     (Σeff_i >= 1 のとき、現行と同じ)
weight_i        = current_manpower_i        (Σeff_i <= 0 のとき、新規フォールバック)
share_i         = total_loss × weight_i / Σweight   (整数除算、IDの昇順、端数は最後の師団)
total_loss(防御) = atk_eff × 100 / max(def_eff + terrain, 1)
total_loss(攻撃) = def_eff+terrain × 100 / max(atk_eff, 1)     ※どちらの分母も下限1、旧`/1000`分岐を廃止
eff              = max(power×readiness_1000×org_ratio_1000/1_000_000, 1)   (power,readiness,org比がすべて正の場合のみ)
```

## 34. outgoing/incoming責務分離

outgoingは既存の実効戦力(補給・装備・manpower・組織率のmin式は不変)で決める。incomingの配分は、実効戦力が正のあいだは既存どおり実効戦力比、陣営全体が0のときだけ現在manpower比という2段構成に分離する。「戦えない=攻撃も受けない」という結合は、陣営全体が0のケースで解消される。一部だけ0の師団は、同陣営に実効戦力が正の師団が生存する間は前線の師団が被害を受け持つ(隊列の前の師団が吸収する現行の意図を保つ)。
