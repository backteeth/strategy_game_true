## 5. Oceanicの税率振動7回の原因

`p27_002_c_residual_fiscal_self_stabilization_e2e_test.rs`と**同一の30日固定暦**を再現する一時診断(`tests/p28_005_pre_002_oceanic_trace_temp.rs`、建設キュー差分イベント・税率反転イベント付き)を使い、`P28RAIL=0.9`(R0)で実際に「7回」を再現した上で、各反転を時系列で特定した。

### 5.1 Oceanicの税率反転(R0適用、120か月)

| # | 月 | 反転前→後 | 直前の建設イベント |
|---|---|---|---|
| 1 | m26 | 0.11→0.12(下降→上昇) | m26: Oceanicが州9・23・24・25・27を領有(州8を喪失、割譲イベント)。同月、州9にFactory lv1着工(優先度2、IndustrialGoods不足) |
| 2 | m42 | 0.13→0.12(上昇→下降) | m39: 州9 Factory lv3着工 |
| 3 | m43 | 0.12→0.13(下降→上昇) | (建設イベントなし、収支の符号反転のみ) |
| 4 | m51 | 0.13→0.12(上昇→下降) | m48: 州9 Factory lv4着工 |
| 5 | m52 | 0.12→0.13(下降→上昇) | (建設イベントなし) |
| 6 | m59 | 0.13→0.12(上昇→下降) | m57: 州9 Factory lv5着工 |
| 7 | m118 | 0.12→0.13(下降→上昇) | (建設イベントなし。m120にRailway m9 lv1着工) |

反転4回(#2〜#5)は月42〜52の10か月間に集中し、税率0.12と0.13の間を往復している。Railwayの着工はm12(州8、まだ喪失前)とm120(州9、120か月の最終盤)の2回だけで、**振動が集中する月42〜59の間にRailwayの着工は1件もない**。

### 5.2 判定

1. **均衡税率付近での小幅な往復か、不安定な再発か**: 前者。全120か月を通じ税率は`0.11〜0.15`の狭い範囲(実質的には0.12⇔0.13の1段)に留まり、国庫は`4,503〜12,920`、加重LSは`65.66〜76.22`で健全に推移した(いずれも崩壊の兆候なし)。P27-002-C-PRE-001が問題視した候補0〜6の「44〜118回、振幅が拡大しながら崩壊に向かう」振動とは性質が異なる。
2. **各反転の直接原因**: Railwayではなく、**Factory建設(優先度2)による経常支出の階段状の増加**と、州9の人口増加による行政費のわずかな増分が、収支をゼロ近傍で行き来させたことが直接原因(#1・#2・#4・#6はFactory着工直後、#3・#5・#7は着工なしでも収支符号が反転)。`process_country_finance`の`monthly_balance = income - expenses`はRailwayの建設支払い(`treasury`のみ変動)を一切参照しないため、Railway自体が反転の直接原因になることはない。
3. **Railwayを建てない条件との差**: 「Railwayなし」(現行挙動)でも同じ月(m26)に同じ領土変化(州8→州9等)が起こり、振動3回(m21・m59・m101)、値域は同じ`0.11〜0.15`・国庫`4,521〜12,920`・LS`65.66〜76.22`だった。**Railwayの有無で健全性の指標(値域・国庫・LS)はほぼ変わらないが、反転の正確な月と回数だけが変わる。** これは、R0がm12に州8へRailwayを1件着工したこと(建設費800の支払い)が、その後の州9のFactory建設が可能になる月をわずかに(数か月)前後させ、月単位の収支符号が変わる経路依存的な結果である。
4. **120か月後に収束するか**: この一時診断では120か月以降も測定していないが、m59以降m118まで59か月間反転がなく(直近の反転からの経過期間が伸びている)、振幅も拡大していないことから、収束方向にあると判断する。
5. **既存の「0〜3回」という基準の評価**: この基準は反転の**回数**だけを見ており、**振幅**(税率が何段動いたか)・**健全性**(国庫・LSが崩壊に向かっているか)を見ていない。今回の7回は、値域・国庫・LSのいずれの指標で見ても現行(3回)と同等の健全性を示しており、回数だけの上限は経路依存的なノイズに対して脆弱すぎる。PRE-001§11論点2の推奨(Oceanicについては「国庫<0の月が0、かつ税率≤0.25」への置き換え)は、この実測によって具体的に裏付けられる。回数の上限自体を完全に廃止するのではなく、**振幅(反転前後の税率差の最大値)にも上限を課す**(例: 反転が起きる範囲は0.02以内)ことで、真に不安定な振動(候補0〜6のような拡大型)は従来どおり検出できる。

## 6. Railway案の再設計候補(R0〜R3)

### 6.1 R1: 対象州の絞り込み(雇用率<0.7を追加フィルタ)

**設計**: R0の物流比率<0.9条件に加え、`雇用率(employed_workforce / total_workforce) < 0.7`の州だけを対象にする(雇用率が高い州は物流<0.9でもLSペナルティを受けないため、Railway投資が不要という仮説)。

**結果**: **A_all条件でDwarfが新たに崩壊する**。

| 指標(360〜600か月、A_all世界) | R0 | R1 |
|---|---|---|
| Dwarf 最大税率 | 0.23 | **1.00** |
| Dwarf 国庫<0の月数 | 0 | **239/600** |
| Dwarf LS<32の月数 | 0 | **249/600** |
| Dwarf 480か月国庫 | 2,893 | **−22,398** |
| Dwarf 600か月国庫 | 2,590 | **−47,232** |

他5か国・現行世界・A_war世界ではR0とR1は完全一致した(Dwarf以外に差はない)。

**原因**: Dwarfは1827/03にA_all世界の戦争で敗れ、6州中5州を失って1州(州20)だけに縮小した。この州20は雇用率が0.68〜0.70の境界上で推移し、R1の判定(`emp >= 0.7`なら除外)がこの境界をまたいで断続的にON/OFFする。除外されている月の間にLSが低下し、州20の物流比率は0.83で0.9未満のまま放置され、雇用率が僅かでも0.7を超えた月にRailway建設の機会を逃す。さらにこの時期、建設キュー(上限2件)がMilitaryFactory(戦時建設)とFactory(優先度2)で埋まり、Railwayが割り込めない月が続いた。R0(雇用率フィルタなし)では、同じ州20が物流比率だけで一貫してRailwayの対象になり続けるため、この境界依存の保護漏れが起きない。

**結論**: 対象を絞ることで保護に「穴」ができ、境界付近で保護が途切れる州がある場合に新たな崩壊経路を生む。**R1は採用しない**。

### 6.2 R2: 発動時期と優先順位の調整(優先度2の前にRailwayを評価)

**設計**: Railway評価を優先度2(原材料/IndustrialGoods事前開発)より**前**に移動する。優先度2がキュー枠を占有してRailwayを締め出す(§6.4相当)可能性を検証する狙い。

**結果**: 3条件・600か月のすべてのチェックポイントで**R0と完全に同一の数値**(税率・LS・国庫、桁まで一致)。Oceanicの税率反転イベント・Railway着工イベントの日付・回数も**完全一致**(m12・m120、7回)。

**原因**: Dwarfの州20やOceanicの州9で、優先度2の「原材料/IndustrialGoods不足」条件と、Railwayの「物流比率<0.9」条件が同じ月に**同時に**成立することは稀で、実際に優先順位の入れ替えが結果を左右する月は今回の3条件・600か月の範囲では発生しなかった。Railwayの着工が遅れる真因は、**優先度2による締め出しではなく、対象州の物流比率が0.9を下回るまで人口増加を待つ必要があること**(§6.4)と、**3か月分の経常支出という予備資金要件**である。

**結論**: 優先順位の入れ替えは安全だが利益もない。複雑さが増えるだけで副作用は減らないため、**R2は採用しない**(R0がこの点で誤っていないことの確認として有用)。

### 6.3 R3: 段階的な建設と完成後の再評価

**設計の検討**: 仕様が比較を求める「連続してRailwayを発注する方式」と「1段完成後に再評価してから次を決める方式」を吟味したところ、**R0は既にすべて後者である**。`try_wartime_supply_construction`と同じ形の判定は、毎月の評価のたびに現在の物流比率が最も低い州を選び直し、その州に既にRailwayが建設キューにあれば(`queued`判定)何もしない。つまり1段が完成してキューが空くまで、同じ州へ次のレベルを再発注することはなく、他の州の状態が変われば次の対象も変わる。これは「連続発注」ではなく「都度再評価」そのものである。

**結論**: R3として独立に実装・測定すべき別設計は存在しない。R0の測定結果(§4.2、§7.4相当)がR3の測定を兼ねる。
