### 1.1 現行コード(FIX1後)の処理(再確認)

- **Step 1:** 州を `StateId` 昇順に走査し、建物 × 入力資源ごとに需要 `base × level × t`(`t = min(労働力比, 物流比)`)を集計する。
- **Step 2:** `sat = clamp(月初備蓄 / 需要合計, 0, 1)`(資源ごと、全消費者で共通)。
- **Step 3:** `BuildingType::ALL` 順(Mine → Factory → MilitaryFactory)の外側、`StateId` 昇順の内側。`planned_op = min(労働力比, 物流比, 入力資源 sat の最小)`(破産時 ×0.8)。FIX1 が、その時点の備蓄(Mine の当月産出と先行 entry の消費を反映)で賄える最大稼働率へ下げ、全入力を原子的に引き落としてから産出する。
- したがって現行の実効的な優先順位は「**Factory が先、MilitaryFactory が後**」(処理順)である。ただし Dwarf では Mine 産出が先に加算され、定常状態では Iron 収入が消費を賄うため、これは大きな制約にならない。

## 2. 比較する条件(正確な定義)

全候補は同一の FIX1 実装の上に、`sat` を**(建物種別, 資源)単位**に拡張して測定した。`want(b, r)` = 建物種別 b の資源 r の需要合計(`base × level × t` の州合計)。`stock(r)` = 月初備蓄(Step 2 と同じ時点)。`op` の決定は現行どおり `min(労働力比, 物流比, min_r sat(b, r))`、続いて FIX1 のクランプ。

| 名称 | 規則 |
|---|---|
| **D0** | 現行本番。`sat(b, r) = clamp(stock(r) / Σ_b want(b, r), 0, 1)`(全消費者で共通) |
| **D1** | **MilitaryFactory 優先**。各資源 r について、まず MilitaryFactory が `min(want, stock)` を確保し、残りを他の建物へ `BuildingType::ALL` 順に `min(want, 残り)` で確保する。`sat(b, r) = 確保量 / want`。対象資源=全入力資源(実際に競合するのは Iron のみ)。同順位時の決定順=`BuildingType::ALL` 宣言順。州・entry 単位の按分は建物種別内で共通の `sat` を使うため、州の `StateId` 順には依存しない(entry の逐次消費は従来どおり `StateId` 昇順で、FIX1 のクランプが総量を守る) |
| **D2** | **需要比例按分**(現行の規則)に、他資源が律速で使い切れない配分を戻す再配分を最大8回反復する(スラック再配分)。対象=全入力資源 |
| **D3** | **D1 + 解放**。MilitaryFactory は全入力の `stock / want` の最小を `m` とし、全入力を `want × m` だけ確保する。つまり IG が律速なら Iron の確保も `m` に下げる(使えない分を確保しない)。他の建物へは `(stock − MilitaryFactory確保) / Σ want(他)` を共通の `sat` とする |
| **D4**(追加) | **ゲート付き D3**。`stock(IndustrialGoods) ≥ 3 × want(MilitaryFactory, IndustrialGoods)`(月間IG需要の3か月分)なら D3、そうでなければ D0。閾値3はこの1点のみ測定(調整していない) |

D4 は、D1/D3 の副作用を実測で説明した後に、副作用の小さい候補として追加したものである(依頼 §3)。D0〜D3 の定義は、P28-010-PRE-002 §6 の定義と同一の規則である。

## 6. 因果の説明

### 6.1 Dwarf の Iron 枯渇前後(月次、D0 / D1)

| 月 | D0 Iron備蓄 / Factory引落し / MF引落し / MS月産 | D1 同 |
|---|---|---|
| m060 | 1,362 / 47.4 / 54.8 / 183 | 同一 |
| m096 | 274 / 65.0 / 105.7 / 352 | 同一 |
| m099 | 89 / 64.9 / 105.6 / 352 | 91 / 62.3 / 105.6 / 352 |
| m100 | 51 / 58.9 / 87.5 / 292 | 95 / **0.0** / **105.6** / 352 |
| m120 | 49 / 58.6 / 49.9 / 166 | 101 / 0.0 / 110.6 / 369 |
| m240 | 108 / 167.6 / 77.7 / 259 | 260 / 4.0 / 147.1 / 490 |
| m360 | 127 / 184.2 / 58.1 / 194 | 243 / 0.0 / 145.9 / 487 |

- Iron が尽きる m100 まで D0 と D1 は同一。以後 D1 は、収入約109を MilitaryFactory に使い切り(D0 の約2倍)、Factory の Iron 引落しは 0 になる。
- D1 の MilitaryFactory は m240 以降、稼働率 0.6 前後で、Iron 備蓄 260 が**余る**。そこでの制約は Iron ではなく労働力・物流(`t`)である。つまり D は Iron 律速を解消し、次の制約へ移すだけで、MS の上限は MilitaryFactory の Level と `t` で決まる。
- **MS の増産は募兵に吸収される。** 月間補給需要は 330 → 480(m108、Division 11→16)→ 660(m300、22)に増え、供給 369 → 490 を追う。不足率は 19.3→14.3%(m120)、26.2→16.7%(m360)と改善するが、絶対日数は 360か月で 29,023 → 27,327(−5.8%)に留まる。供給を増やすと AI が Division を増やす(D1 で Dwarf 11→22)ため、効果の大半は「同じ不足率で部隊を増やす」方向へ流れる。
- **Factory の Level**: D1 の Dwarf は Factory を 35 件着工(D0: 29)。IG が減ると AI が Factory を増設するが、増設した Factory は m100 以降の約80か月、Iron を受けられず動かない(Factory 引落し 0)。IG 備蓄は 3,942(m100)から 1,404(m150)へ減った後、Iron 収入が 150→235 に増えた m180 から回復する。D4 のゲート(3か月分)は、Dwarf では全チェックポイントで D1 と完全に一致し、発火した形跡がない(IG 備蓄の最小観測値は 1,404)。

### 6.2 FIX1 前提の Factory 側の副作用

- IG はどの経路でも福祉・財政・人口に使われない(MilitaryFactory の入力のみ)。Factory を飢餓させても、生活水準・国庫へは**直接の経路を持たない**。経路は維持費(`maintenance_cost × level × op`)の減少と、IG 枯渇による MilitaryFactory の IG 律速だけである。
- 雇用は `required_workforce × level` で決まり、稼働率に依存しない(建物 Level を変えない限り変わらない)。D は Level を変えない。

### 6.3 Passguard の振動の原因(D1/D3)

D1 の Passguard(制御診断、月次、Factory/MF の Iron 引落しと IG 備蓄)で、m018 以降を追った。

| 月 | D0 | D1 |
|---|---|---|
| m017 | Factory 11.4 / MF 34.3 / IG 18 / MS 114 | 同一 |
| m018 | 11.4 / 34.3 / IG 18 / MS 114 | **Factory 2.5** / MF 34.3 / **IG 4** / MS 114 |
| m019 | 10.8 / 32.3 / IG 18 / MS 108 | Factory 2.8 / **MF 8.1** / IG 4 / **MS 27** |
| m020 | 9.3 / 27.8 / IG 18 / MS 93 | 11.4 / 8.4 / IG 17 / MS 28 |
| m021 | 9.3 / 27.8 / IG 18 / MS 93 | 14.3 / 42.1 / IG 18 / MS 140 |
| m029 | 11.6 / 34.8 / IG 18 / MS 116 | 14.3 / 45.8 / IG 19 / MS 153 |
| m034 | 11.6 / 34.8 / IG 18 / MS 116 | 1.5 / 13.1 / IG 2 / MS 44 |

1. D1 は MilitaryFactory に Iron を先に確保する。Factory は残りしか得られず、IG 産出が落ちる(m018: IG 備蓄 18→4)。
2. IG が尽きた MilitaryFactory は IG 律速になり(m019: MS 108→27)、確保した Iron を使えない。
3. 使われなかった Iron が備蓄に残り、翌月の Factory が動いて IG が回復する(m021: MS 140)。回復した IG をまた MilitaryFactory が使い切り、再び Factory が飢える。
4. **月ごとに MS が 27〜153 の間で振れる。** 維持費は稼働率に比例するため、月次支出も 252〜328 の間で振れ、AI の税率が 0.21〜0.24 の間を往復する。国庫がゼロ付近の Passguard では、これが破産月(生活水準 −0.5、稼働率 ×0.8)を増やす(240か月の破産月数は D0 17、D1 23、D3 43。P28-010-PRE-002 での実測で、Passguard は FIX1 の影響を受けない)。
5. **LS の差の定量(D3 の −6.5)**は破産月の積み上げと税収の低下(LS が下がると税収が下がる循環)で、振動が始点であることまでは確認した。D1 と D3 の差(LS 68.5 と 63.5)を月単位で分解することまでは行っていない。

D3 は「使えない Iron を確保しない」ため、同月内の IG 律速には対応するが、**月をまたぐ IG の枯渇→回復の振動は防げない**。D4 は IG 備蓄が3か月分を割ったとき D0 へ戻すため、Factory が IG 産出を続け、この振動を起こさない(Passguard 240か月は D0 と完全に一致)。

### 6.4 Ferrowyn の生活水準低下

制御診断で、D0 の Ferrowyn は m230 まで Division 7、LS 67.2。D4 は m230 に LS が 67.22→65.38 に下がり、m231 に Division が 8 になる。つまり**供給改善により AI が 8 個目の Division を募兵し、動員で民間労働力が減った**ことによる(経済や Factory の悪化ではない)。人口加重で −1.6(67.0→65.4)。

### 6.5 Arcadia の順位低下(自然運用)

D1 の自然運用では、Dwarf+Elfin 対 Arcadia の戦争(war5、1806/03/02 開戦)が 1823/03/05 に Dwarf 側の勝利で終結する(D0 では 1830/01 時点も継続中)。その後に新しい戦争が 1823〜1824 年に4件開戦する。Arcadia の国庫は 4,551 → 2,511、LS 48.7 → 44.0(LSw 52.7 → 45.7)、順位 4 → 6。**制御診断(Arcadia のみに適用)では Arcadia は不変**であり、これは他国の補給改善を通じた世界経過の変化である。

## 8. 採用判定

| 観点 | D1 | D3 | D4 |
|---|---|---|---|

### 8.1 結論

1. **D1・D3 は単独では採用しない。** Passguard 型(IG 備蓄が乏しい)で、IG 枯渇の振動による財政・生活水準の悪化が確認された(§6.3)。
2. **D2 は採用の対象にならない**(D0 と同一で効果がない)。
3. **D4 を実装契約の候補とする**(Passguard を D0 に保ちつつ、Dwarf・Ferrowyn・Elfin の効果を得る)。ただし次の理由から、採用の確定にはユーザーの判断を要する:
   - D0〜D3 の外の追加案であり、閾値(3か月分)は1点しか測っていない。
   - 供給の改善が AI の Division 増と戦争の連鎖を通じて世界経過を大きく変える(戦争 9→13、Arcadia の順位 4→6、Ferrowyn の LS −4.4)。これはゲームバランスの判断である。
   - 決定論的な1軌跡で、複数seed の検証ができない(仕組みがない)。
4. **D0 維持も正当な結論である**(補給不足は引き続き残るが、会計は正しく、世界経過は現状のまま)。
