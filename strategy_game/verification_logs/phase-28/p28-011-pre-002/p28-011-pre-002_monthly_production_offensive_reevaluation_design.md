### 要旨

1. **月初の生産が MilitaryAi より前に反映される。** 同じ日の順序は `handle_monthly_economy` → 日次補給消費 → … → `handle_daily_military_ai`(§2.1)で、AI は「生産 + その日の消費」後の備蓄を見る(1808/08/01: 789)。
2. **P28-011-PRE-001 の「評価日 08/03」は誤りだった。** AI の評価周期は `年×365 + 月×30 + 日` の日番号で数えるため、31日と翌月1日が**同じ番号**になり(1808/07/31 と 08/01 は共に 660161)、実際の評価は **07/31 → 08/04** だった。備蓄が 70日分(770)以上だったのは 08/01(789)・08/02(778)の2日で、08/03(767)は未満、08/04 の評価時は 756 だった。**結論(窓を逃した)は変わらない。**
3. **R2(月初に攻勢開始だけを追加評価)は、この窓を実際に捉えた。** 1808/08/01 に Dwarf の 11 Division が移動を開始し、08/05 に目標州2を占領、**1808/08/15 に AttackerVictory**。これは R2 の実測であり、以前の制御診断(日次評価)の結果を仮定したものではない(同一日付になった)。
4. **R2 は WarId(9) を解消しない。** 月初備蓄は 125(15.6日分)で、70日分の必要量 560 の 22%。
5. **R2 は世界の経過を 1801/11/01 から分岐させる。** 同じ「備蓄が 70日分を月初に超える」型の攻勢開始が、通常の戦争でも 1〜2日早まる。長期では戦争数 10 → 13、Ferrowyn が首都を失い 1847年に国庫がマイナスに入る世界になり、WarId(5) 相当の停止(WarId(12))が別の戦争で再現する。**R2 は「窓の見逃し」の型を直すが、停止の構造(生産 < 需要)は直さない。**
6. 二重実行は防げる。ただし防止の判定に `last_evaluated_day == 今日` は使えない(日番号の衝突のため)。**評価前に「評価対象でない国家」を確定する**必要がある(§8)。

## 7. 最初の分岐と因果

| 項目 | 内容 |
|---|---|
| 最初の分岐日 | **1801/11/01**(Dwarf、WarId(4): 対 Ferrowyn) |
| 直接原因 | 月初の生産で備蓄が 355.3(≥ 70日分 = 5 Division × 70 = 350)に達した。R0 は翌 11/02 の定期評価で攻勢を開始する。R2 は 11/01 の月初に開始した(1日早い) |
| 連鎖 | WarId(4) の終結が 1802/01/16 → 1802/01/15。Ferrowyn の以後の状態(Division 1 → 戦闘中)が変わる |
| 次の分岐 | 1808/08/01: WarId(5) の攻勢開始(§4)。WarId(5) 終結(08/15)→ Dwarf・Elfin の戦力が空き、10/02 に Ferrowyn へ宣戦(WarId(8)、目標: 州22=Ferrowyn の首都) → 10/12 に勝利 |
| 帰結 | Ferrowyn は首都州22を失い、領土が 3 → 2 州。国庫が減少し、税率が 0.99 に達し、1847/04 に国庫がマイナス |

分岐は「月初に備蓄が 70日分を超えた」型の攻勢開始を、翌日以降でなく月初に早めるという R2 の性質から生じる。**R2 の効果の本質は、停止を解消することではなく、開始の評価日を月初に寄せること**である。

### 7.1 R2 の限定版の検証(補足)

「備蓄ゲートが閉じていたフラグ(`offensive_supply_blocked == true`)の前線だけを対象にする」限定版 R2s も実測した。1801/11/01 の時点で、そのフラグは true のまま(月初の生産で解除可能になる直前)であったため、R2s も R2 と**同一の経過**になった(戦争・国庫・Division が一致)。つまりこの型の分岐は、R2 の対象を絞っても避けられない。

## 8. 二重実行の防止

| 項目 | 結果 |
|---|---|
| 定期評価と月初が重なる日 | Dwarf で 600 か月中の月初 600 回のうち **258 回**で重なる。R2 は、**評価前に確定した「その日は評価対象でない国家」**(`current_day − last_evaluated_day < 3 && !dirty`)だけを対象にするため、これらの日は何もしない |
| `last_evaluated_day == 今日` では防止できない | 日番号の衝突(31日と翌月1日が同番号)のため、前日の評価と同じ値になり、R2 が全く動かなくなる(実測: 最初の実装は R0 と同一の結果になった) |
| R2 が更新しない状態 | `last_evaluated_day`、`dirty`、`estimated_*`。R2 の実行によって、次回の定期評価の日付は変わらない |
| 攻勢開始の冪等性 | 対象は `stance != Offensive` の前線だけ。`Offensive` に切り替えた後は、同じ日の `handle_daily_frontline_plans`(後段)が移動命令を出し、翌日以降の通常の移動命令と同じ経路を通る。進捗の巻き戻し・命令の重複は観測されなかった |

### 9.1 System順序への依存

R2 は `handle_daily_military_ai`(MilitaryAi Set)の中で実行するため、追加の順序制約は不要。依存するのは既存の次の2点: (a) `handle_monthly_economy` と `process_daily_military_supply_consumption` が同じフレームの MilitaryAi より前(Economy Set は MilitaryAi Set より前)、(b) `MonthChangedMessage` が `DayChangedMessage` と同じフレームで発行される(`advance_game_date`)。(b) が崩れる(月の変更が別フレームになる)と R2 は動かない。

## 10. 設計判定と次の原子的タスクの契約

### 10.1 判定

R2 は技術的に安全に実装できる(永続状態なし、二重実行なし、冪等、既存ゲート維持)が、以下を踏まえ**採否をユーザー判断とする**。

| 観点 | 評価 |
|---|---|
| WarId(5) 型(月初に一時的に 70日分を超える窓の見逃し) | **解消**(14日で終結) |
| WarId(9) 型(月初のピークが 70日分に届かない) | **解消しない** |
| 同種の停止の再現 | 別の戦争(WarId(12))で再現。継続戦争は 2 → 1 に減るが、停止の構造は残る |
| 世界の経過 | 1801/11 から分岐。戦争 10 → 13。Ferrowyn が首都を失って国庫が負(国家の存続に関わる変化) |
| 正常な勝利・P28-007/P28-008 の契約 | 変更なし(講和処理・終結規則は無変更。恒久テストへの影響は未実施。実装時に検証) |

### 10.3 独立した後続監査候補(本タスクでは扱わない)

1. WarId(9) 型と「募兵停止 40日 / 攻勢再開 70日」の構造(P28-011-PRE-001 §6.1)。生産が需要を下回る定常状態で、備蓄が 70日分に届かない問題。P28-004 の硬い募兵ゲートは、検証なしに再採用しない。
2. 評価周期の日番号 `年×365 + 月×30 + 日` が 31日と翌月1日で衝突する問題(Low、§11)。
